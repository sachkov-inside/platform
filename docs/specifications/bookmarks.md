# Закладки на материалы

Статус: спецификация поставляется в [#478](https://github.com/sachkov-inside/platform/issues/478);
реализация — отдельные delivery issues по этой спецификации.

## Пользовательский результат

Авторизованный Account добавляет доступный Material в личные закладки и убирает оттуда, а на
отдельной странице `/bookmarks` видит свои закладки одним списком и открывает материал из него.
Закладка — личная связь `Account ↔ Material`, а не доступ: она не даёт право читать защищённый
material. Закладки доступны и Free non-member для открытых материалов.

- Действие на Reader любого формата: «В закладки» / «В закладках», повторное нажатие снимает
  закладку. Пустое состояние, pending, ошибка и откат оптимистичного состояния входят в результат.
- Анонимный посетитель получает предложение войти; открытые материалы читаются без входа.
- Список отсортирован от новых к старым; снятый с публикации material скрывается, защищённый без
  действующего доступа показывается закрытой карточкой. Закладка при этом сохраняется.
- Смена профиля, Telegram link или окончание Membership не сбрасывают закладки; logout очищает
  личное представление в браузере.

## Владение и устойчивые ссылки

Bookmarks — новый state-owning backend Module со своей схемой PostgreSQL `bookmarks` (ADR 0003).
Accounts владеет identity, Materials/ContentLibrary — опубликованным составом и проекциями,
ContentAccess — разрешением доступа.

Внешние `accountId`/`materialId` хранятся как opaque UUID; cross-schema SQL, views и foreign keys
отсутствуют. Текущий Account разрешается только из доверенной сессии; `accountId` из тела запроса
не принимается. Публичные ответы и кэши не содержат персональных полей; personal reads изолированы
по Account.

Добавление проверяет актуальное разрешение ContentAccess на опубликованный Material через
`authorize` с enforcement point `bookmark_change`. Снятие собственной закладки разрешено по opaque
ID после окончания Membership или снятия с публикации. Закладка никогда не даёт право читать body
или связанные ресурсы.

## Хранение

`bookmarked_materials` имеет primary key `(account_id, material_id)`:

| Поле | Значение |
|---|---|
| account_id, material_id | UUID внешних устойчивых identities |
| bookmarked_at | Серверное время добавления закладки |

Наличие строки означает закладку. Добавление идемпотентно (повтор сохраняет исходный
`bookmarked_at`); удаление идемпотентно. Отдельной версии, истории переходов и receipts нет: это
простая закладка. Индекс `(account_id, bookmarked_at DESC, material_id)` поддерживает список.

## Interface и проверка

Module предоставляет `addBookmark`, `removeBookmark`, bounded `getBookmarkStates` для набора до 100
ID и постраничный `listBookmarks` (cursor, от новых к старым). Список собирается композицией строк
Module с существующим швом публичных проекций материалов: снятые с публикации скрываются,
защищённые без доступа сохраняют `locked`. Точные REST paths/codecs вводятся в source schemas с
генерацией OpenAPI/Web client без ручного редактирования generated files.

Backend-тесты проверяют реальный PostgreSQL: идемпотентность add/remove, изоляцию двух Account,
отказ при отсутствии доступа, снятие после потери доступа, скрытие unpublished и возврат после
republish, порядок и пагинацию, границы batch, валидацию входа. Web-тесты проверяют BFF-границу,
маппинг в безопасные material previews и отсутствие публичного раскрытия. Пользовательская
вертикаль проверяется Playwright и Storybook; merge/deploy остаются owner gates.
