# Гибридный поиск Помощника и pgvector в образе базы

Владелец принял решение 08.11.2026 по итогу «Помощник: технический прототип» (#1984).
Устройство поиска: «Помощник: техническое устройство» (#1983). Исследование: «Помощник:
поиск по материалам» (#1978). Границы спецификаций: «Помощник: границы спецификаций первой
версии» (#1988).

## Контекст

Решение #1983 начинало с поиска по словам и добавляло векторы, если прототип покажет выигрыш
от 5 пунктов. Прототип сравнил варианты на 470 разделах курса AI Engineering и 68 вопросах
с известным разделом. Нужный раздел попал в первые 10:

- по словам с 2-5 запросами модели: 59%;
- по смыслу, `qwen3-embedding-8b`: 90%;
- гибрид RRF 1:1 с `qwen3-embedding-8b`: 85%.

На 9 живых вопросах из группы Telegram поиск по словам нашёл 33%, по смыслу 78-89%. Слова
всё же нашли 5 вопросов раньше векторов. Это точные строки: команды, имена, термины курса.

## Решение

Помощник ищет гибридом. Списки по словам от запросов модели сначала сливаются в один. Затем
этот список сливается с одним списком по смыслу через RRF в пропорции 1:1. Слияние 5:1 дало 75%,
потому что слова перевешивали.

- **Части материала** строит Materials по заголовкам `##` и `###` в транзакции Save (ADR 0009)
  и хранит в схеме `materials` с SHA-256 текста. Текст берётся через `materialBlockText`, поэтому
  ответы квизов в поиск не попадают. Блок `agent_prompt` в поиске есть, но модель получает только
  название и ссылку.
- **Части расшифровки видео** строит модуль `videos` по 2-3 минуты, с границами глав, если они есть.
  Источник: субтитры монтажа. Автосубтитры Kinescope нужны только для видео без субтитров.
- **Векторы** считает фоновая задача `pg-boss` по хешу текста. Модель задаёт настройка,
  по умолчанию `qwen3-embedding-8b` через OpenAI-совместимый endpoint. Пока вектора нет, часть
  находит поиск по словам.
- **pgvector** собирается из исходников в образ проекта `ghcr.io/sachkov-inside/postgres`,
  как уже собран pgBackRest. Прототип собрал pgvector 0.8.1 за 18 с, образ вырос на 1 МБ.
- **Индекса нет.** Точный перебор 470 разделов с векторами из 4096 чисел занял 3,5-4 мс,
  4700 разделов 28-31 мс. Перебор ничего не теряет, а приблизительный индекс с фильтром теряет.
- **Доступ** проверяет `ContentAccess` после поиска. Для `available` модель получает текст,
  для `locked` только название и ссылку на курс.
- **Reranker** включается настройкой и по умолчанию выключен. Через 2-4 недели работы его включают
  для половины ходов и сравнивают по оценкам ответов и журналу шагов.

## Отклонено

- **Только поиск по словам.** Он проиграл векторам 31 пункт на своих вопросах и 45-56 пунктов
  на живых.
- **Только векторы.** Они дали больше на замере, но теряют точные строки. Гибрид их страхует.
  Расхождение 90% и 85% проверяют evals.
- **Весь курс в запросе.** Это около 1,5 млн токенов, а права доступа ломают кэш (#1983).
- **Облачные хранилища векторов.** Нет доступа из России, права проверялись бы не у нас (#1983).

## Последствия

- Схема `materials` и схема `videos` получают таблицы частей и векторов. Расширение `vector`
  ставится миграцией.
- Индекс HNSW в pgvector работает до 2000 измерений для `vector` и до 4000 для `halfvec`.
  Вектор `qwen3-embedding-8b` имеет 4096 чисел. Если индекс понадобится, размер вектора нужно
  будет сократить: модель это позволяет.
- Смена модели векторов требует пересчёта всех векторов. Прототип оценил полный пересчёт курса
  до 12 ₽.
