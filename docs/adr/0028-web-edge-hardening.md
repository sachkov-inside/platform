# Защита входа web: HSTS, CSP и ограничение частоты

Решение принято по [#688](https://github.com/sachkov-inside/platform/issues/688) в сентябре 2026 года.
TLS-политика принадлежит Caddy, CSP задаёт web, а ограничение частоты входных запросов работает
в proxy web. Распределение сохраняет защиту во время обслуживания и позволяет считать запросы
там, где ещё известен адрес клиента.

## HSTS ставит Caddy

Системный Caddy добавляет HSTS и в обычный ответ, и в maintenance. Основной домен `sachkov.dev`
и `www.sachkov.dev` получают годовой HSTS без `includeSubDomains`; прежний
`inside.sachkov.dev` сохраняет `includeSubDomains` по решению #421. Preload не включён:
его последствия для доменов и длительное снятие требуют отдельного решения. Next.js не становится
вторым владельцем HSTS.

## `'unsafe-inline'` в `script-src` остаётся

Принятый режим [ADR 0027](0027-web-navigation-and-caching.md) соединяет предсобранную оболочку
и личный потоковый ответ. На этапе принятия решения nonce требовал рендера на каждый запрос,
а SRI внешних файлов не покрывал встроенные flight-скрипты личного ответа. Владелец принял
сохранение `unsafe-inline` 25.09.2026 в #713.

Отключение `cacheComponents` отвергнуто из-за возврата блокирующей навигации. Прослойка,
которая ждёт полный HTML ради вычисления hash, задерживает первый байт до конца личного чтения
и одобряет уже попавшие в документ скрипты. Патч на экспериментальном React отвергнут как
production-зависимость. Замеры и версии этих сравнений сохранены в
[свидетельствах #713](../evidence/issue-713/README.md).

Решение не означает разрешение произвольного HTML автора. Остальные источники CSP ограничены,
`unsafe-eval` разрешён только в разработке. После #1766 закрытые изображения и файлы обслуживает
свой origin через Caddy; production-политика не требует адресов Yandex Object Storage.
Локальная production-сборка стенда получает только явно проверенный loopback origin.
Точный набор директив принадлежит [Next config](../../apps/web/next.config.ts), а не копии в ADR.

Условие пересмотра: стабильный поддерживаемый runtime позволяет убрать встроенные скрипты или
покрыть их nonce/hash без отказа от принятого режима рендеринга и без экспериментального React;
либо сам режим рендеринга изменён отдельным решением. Проверка сентября не является заявлением
о возможностях всех последующих версий Next.js.

## Ограничение частоты считает proxy web

Proxy ограничивает чувствительные входные маршруты до их обработчиков. Caddy используется
в штатной сборке без отдельного rate-limit модуля, а backend видит соединение web, поэтому
выбрана граница web. Перечень маршрутов и пределы принадлежат
[entry-rate-limit.ts](../../apps/web/src/_app/entry-rate-limit.ts).

Адрес клиента берётся из заголовка, который доверенная edge-граница заменяет адресом соединения;
IPv6 группируется по /64. Недоверенный `X-Forwarded-For` не должен позволять обойти предел.
Текущая модель доверия и её проверка принадлежат
[production foundation](../runbooks/production-foundation.md) и
[контракту runtime](../../scripts/production-runtime-contract.test.mjs).

Счётчики ограничены по памяти и живут в одном процессе production web. Перезапуск их сбрасывает;
в `next dev` ограничитель не действует. Это предохранитель, а не распределённая защита от
массовой атаки. Второй экземпляр web требует общего состояния и пересмотра решения.
Интеграции, идущие прямо в backend, сохраняют собственную аутентификацию; ограничитель не заменяет
проверки кода и пароля в backend и Logto.

## Общий потолок отчётов браузера держит обработчик

Предел на один адрес не ограничивает общий журнал, поэтому обработчики телеметрии дополнительно
ограничивают число записываемых строк на процесс (#708). Метрики и ошибки имеют разные бюджеты;
проверки Origin, размера и схемы выполняются до расхода бюджета. Сверх предела ответ `429`
не пишет отчёт, а первый отказ окна оставляет диагностическую строку.

Компромисс: один клиент может исчерпать общий бюджет и временно вытеснить чужие отчёты.
Серверные ошибки идут своим путём. Если потеря клиентских ошибок мешает расследованиям,
нужно пересмотреть пределы и справедливость распределения, а не считать существующий потолок
гарантией доставки всех отчётов.
