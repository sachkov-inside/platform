# Навигация и кеширование web

Владелец принял решение 17.09.2026 в
[#670](https://github.com/sachkov-inside/platform/issues/670): повторные переходы по каталогу
не должны заново ждать полную серверную страницу. Общая часть страницы кешируется,
личная часть читается отдельно. Кеш ускоряет показ, но не выдаёт право на закрытый контент.

## Режим рендеринга

Web использует `cacheComponents` и `partialPrefetching`. Публичные страницы каталога разделяют
оболочку маршрута, общее анонимное чтение и личную границу `<Suspense>`. Личная граница
останавливает предзагрузку через `connection()` до cookie и получения токена. Продукт,
программа, материал, задание и тема сохраняют собственный вид загрузки.

Разделы, целиком зависящие от сессии, и перенаправления до отправки ответа могут оставаться
блокирующими. Клиентские каталоги следуют [ADR 0011](0011-client-owned-library-catalog.md),
а браузерные записи, [ADR 0012](0012-browser-owned-interactive-mutations.md) и
[ADR 0038](0038-one-definition-per-browser-mutation.md). Общее решение не требует переносить
все чтения в браузер или делать каждый маршрут потоковым.

Согласованное исключение из неподвижной геометрии (#1788): личная часть убирает у участника
нижний блок курса «Что входит в курс». Он стоит последним, поэтому сдвигает только подвал
за краем экрана. Разделение на общую и личную части не обещает одинаковый состав страницы всем.

## Что кешируется, а что нет

Общий серверный кеш содержит только результаты анонимного чтения. Тело Material входит в него
только при явно разрешённом backend `cacheScope: "public"`. Ответы с токеном, закрытые тела,
доступ читателя, прогресс и персональные условия продажи не входят в общий кеш.
`"use cache: private"` не используется. Функции общего кеша не видят сессию и сами задают профиль
и тег. Backend остаётся владельцем проверки доступа.

Владелец принял задержку внешних записей каталога до пяти минут: импорт и MCP не получают
отдельный канал сброса web-кеша. Авторская запись через BFF сбрасывает каталог; сбой ответа
тоже может сопровождаться состоявшейся записью, поэтому не является основанием пропустить сброс.
Профили успешного, отсутствующего и недоступного результата различаются. Сбой backend не должен
застывать в предсобранной оболочке.

## Клиентский кеш маршрутов

Каталог имеет отдельное 60-секундное окно памяти страницы. У кабинета, авторской части и оплаты
общего окна нет. Вход, выход и другие полные загрузки сбрасывают память; известное вкладке
изменение доступа или прогресса вызывает обновление соответствующего состояния и маршрута.
Кнопка повтора после сбоя должна перечитать сервер, а не повторно показать сохранённый ответ.

Владелец явно принял 05.10.2026 в #925 остаток: в окне памяти повторный переход может показать
ранее полученное закрытое тело после отзыва доступа из другой сессии. Новый запрос получает
отказ сразу. Это предел повторного показа при навигации, а не обещание удалить уже доставленные
данные или обновить неподвижную открытую вкладку по таймеру.

## Предзагрузка ссылок

Обычная ссылка предзагружает общую оболочку маршрута. Намерение читателя (наведение, фокус,
касание) может запросить общую часть конкретной страницы. Закрытое тело и личное чтение
не должны попадать в спекулятивную предзагрузку. Контекст возврата и позиции программы остаётся
в URL; общий кеш тела не размножается по месту, откуда открыт Material.

## Настоящий 404 до начала ответа

Неизвестный опубликованный юридический адрес проверяется в proxy по локальному списку документов,
до начала ответа. Для адресов каталога допускается потоковый экран «не найдено» с `200` и
`noindex`: синхронная проверка каждого slug перед ответом вернула бы зависимость от backend
на каждый переход и предзагрузку. Это сознательный компромисс из #701.

Админка (`/authoring`) закрыта для гостя и аккаунта без прав (#1879) тем же потоковым экраном
«не найдено» со статусом `200` и `noindex`: решение требует сессии и чтения прав у backend, а proxy
их не читает. Проверку вызывают layout раздела и каждая его страница, потому что layout не
останавливает рендер страниц под ним.

Proxy не читает сессию и backend. Исключение для одноразовой навигационной cookie выхода
`inside.logout-return` из #1496 не превращает её в доказательство входа или доступа.

## Цена решения и пересмотр

Личная часть и сброс кешей требуют явных границ. Один процесс web хранит общий кеш в памяти;
несколько экземпляров потребуют согласованного кеша и инвалидации. Мягкий 404 пересматривается,
если он мешает поиску или список адресов становится доступен web без запроса к backend.
Окно страницы и экспериментальные возможности Next.js перепроверяются при обновлении runtime.
Программа курса и её навигация используют один состав Products по
[ADR 0035](0035-product-catalogue-programme-and-attachments.md).
