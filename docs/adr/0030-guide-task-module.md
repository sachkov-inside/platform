# Задание имеет отдельного владельца и жизненный цикл

Владелец принял решение 05.10.2026 по #939: задание является отдельной сущностью,
а не разновидностью Material. Product Tasks (`product-tasks`, схема `product_tasks`) владеет
заданием, неизменяемыми версиями требований, сдачами ученика и ответом автора.
Исторические имена Guide Task и `guide-tasks` заменены, граница владельца сохраняется.

[ADR 0009](0009-one-mutable-material.md) оставляет Material с одним изменяемым телом.
У задания требования версионируются, а сдача остаётся связана с своей версией. Совмещение
в Materials добавило бы второй жизненный цикл содержимого и чужие данные учеников.
Изменение определения задания не переписывает требования уже принятой сдачи.

Products владеет каталогом, главами и позицией материалов программы по
[ADR 0035](0035-product-catalogue-programme-and-attachments.md). Product Tasks читает эти факты
через интерфейс Products. Состояние доступа получает через ContentAccess; задания не создают
собственных Product Access и не вычисляют их по реальному членству в Telegram.
Адаптер фактов задания подключается выше владельцев в
[ContentAccess composition](../../apps/backend/src/entrypoints/composition/content-access-composition.module.ts).

Поправка #947 позволяет автору показывать задание после материала той же главы или в начале
главы. Такая привязка задаёт представление программы и не делает задание второй разновидностью
Material или отдельной отметкой изучения материала. Изменение расположения не создаёт новую
версию требований. Изменение учебной модели требует отдельного решения, а не вывода из UI-порядка.

Учебный MCP получает инструменты владельца задания; Materials и ContentAccess не импортируют
реализацию Product Tasks ради его сборки. Сохраняются правила ацикличности из
[ADR 0029](0029-acyclic-module-dependencies.md). Legacy PracticeDefinition выводится только
после сохранения требований и переноса реальных потребителей, не по одному наличию нового Module.

Цена отдельного владельца: собственная схема, контракты и явная связь с Product/Chapter.
Она сохраняет историю ученика независимо от редактирования одного Material.
Удаление по требованиям обработки данных остаётся отдельной явной процедурой,
а не разрешением изменять неизменяемые версии обычным редакторским Save.

Текущая реализация: [Product Tasks](../../apps/backend/src/modules/product-tasks/).
Контракты и текущий учебный интерфейс: [platform-v1](../specifications/platform-v1.md).
Проверки: [product-tasks](../../apps/backend/test/integration/product-tasks.test.ts) и
[submission-review](../../apps/backend/test/integration/product-task-submission-review.test.ts).
