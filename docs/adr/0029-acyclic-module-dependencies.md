# Ацикличные зависимости между Modules

В #695 и #732 принято решение: граф импортов между backend Modules не имеет циклов.
Type-only import, реэкспорт и динамический import тоже являются зависимостью, даже если
при исполнении часть из них исчезает. Проверка рассматривает полный граф и называет файлы
рёбер цикла, а не только последний добавленный импорт.

Цикл разворачивается узким port потребителя, ответом владельца операции или переносом общего
значения ниже обоих Modules. Сборка адаптеров находится над владельцами в entrypoint composition.
Неиспользуемый runtime-адаптер не удерживается в production ради единственного теста.

Публичный `index.ts` содержит только используемый внешний интерфейс. Внутри своего Module
код импортирует собственные файлы напрямую. Экспорт без внешнего потребителя не сохраняется
«на будущее». Отдельный интерфейс не нужен для каждой локальной функции.

Цена решения: при новом сценарии приходится явно определять направление зависимости и владельца
факта. Универсальный сервис, скрытый `await import` или глобальный модуль не являются обходом
правила. Старые глобальные adapters в истории #732 описывают этап устранения циклов,
а не обязательную нынешнюю сборку Materials или Account Rights.

Правило проверяет [check-backend-architecture](../../scripts/check-backend-architecture.mjs).
Текущие владельцы указаны в [карте контекстов](../product/domain-context-map.md),
критерии ревью в [стандартах backend](../../apps/backend/CODING_STANDARDS.md).
Пример нынешней сборки: [ContentAccess composition](../../apps/backend/src/entrypoints/composition/content-access-composition.module.ts).
Непрозрачная передача одной транзакции по [ADR 0039](0039-opaque-transaction-handoff.md)
не разрешает обратный импорт или обращение к чужим таблицам.
