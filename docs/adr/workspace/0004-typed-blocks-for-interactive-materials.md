# Интерактивные материалы через типизированные блоки

> Решение перенесено из [Workspace](https://github.com/sachkov-inside/workspace/blob/125cbde1631a0c9c314a29c829961ab8aa785a06/docs/adr/0004-typed-blocks-for-interactive-materials.md).
> Область действия и текущий статус указаны в [индексе](README.md).

2026-09-11 владелец выбрал развитие материалов в сторону визуальных и интерактивных уроков и
подтвердил порядок: сначала единый источник схемы документа и реестр блоков, затем рост словаря
блоков. Канон тела материала остаётся versioned structured document (`Material.body`,
`schemaVersion`), как рекомендует
[модель авторинга](../../research/platform-content-authoring-model.md). Интерактив и визуал
добавляются новыми типизированными блоками, а не свободной вёрсткой автора.

Markdown и Obsidian остаются авторским слоем. Оригиналы готовятся в Inside Content и переносятся
на Platform ([product/README.md](../../product/README.md)); Markdown является профилем импорта и
экспорта, а не authority после создания draft. Каждый новый блок обязан иметь читаемую запись в
Markdown, иначе оригинал в vault перестаёт быть редактируемым текстом.

Страница-урок как файл HTML + CSS рассмотрена и отклонена. Свободная вёрстка лишает платформу
полнотекстового поиска и оглавления, которые строятся из тела материала, ломает прогресс чтения и
закладки, опирающиеся на адресуемые блоки со стабильным `nodeId`, распускает единый вид по
страницам и открывает исполнение авторского JavaScript внутри приложения с подпиской и оплатой.
В Obsidian такой файл перестаёт читаться и осмысленно сравниваться в Git. Markdown как канон
отклонён ранее в модели авторинга.

Свободный HTML допустим единственным способом: отдельный изолированный блок embed, содержимое
которого хранится ассетом и исполняется в песочнице. Это исключение для редких демонстраций, а не
способ вёрстки урока.

Цена решения — стоимость одного блока. Сегодня блок требует согласованных правок в схеме
документа, правилах валидации, рендере, извлечении текста для поиска и в редакторе, а схема
существует двумя копиями, обязанными совпадать. Поэтому словарь расширяется только после общего
источника схемы и реестра блоков и растёт по реальной потребности руководств, а не запасом.

Owning repository — Platform. Реестр блоков, контракт импорта из Markdown и состав словаря
являются application-решениями Platform и фиксируются там. Workspace удерживает только эту границу
и связь с авторским процессом Inside Content.
