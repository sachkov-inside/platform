# Страница продукта из данных источника

Владелец принял решение 17.09.2026 в #671: текст страницы продукта поступает из авторского
источника вместе с составом, а оформление выбирает именованный реестр компонентов. Правка текста
не должна требовать выпуска web или сравнения `slug` с особым именем курса.

Products владеет сохранённым описанием страницы и именем оформления. Source-scoped импорт
валидирует их у владельца данных до записи. Описание состоит из типизированных блоков,
а не свободных HTML/CSS/JavaScript. Иллюстрации и поведение оформления остаются в коде.
Неизвестное оформление читается общим шаблоном; непригодное описание не показывается как достоверное.

Постоянная идентичность продукта задаётся source ID и Product ID, а `slug` является изменяемым
адресом. Каталог, главы и история читателя связаны с постоянной идентичностью. Переименование адреса
не переносит эти связи на новый продукт и само по себе не создаёт redirect старого адреса.

Импортированный Product сохраняет одного владельца полей. Web-редактор и MCP не обходят source
ownership. Пакет, не задающий описание, оформление или адрес, сохраняет прежние значения;
явное снятие описания отличается от пропуска поля. Введение импортированного продукта также
пишет источник по поправке #845 от 08.10.2026. Для созданного в Platform продукта действует
его обычный редакторский интерфейс.

Backend-схема решает пригодность к записи. Более мягкий web decoder читает сохранённое внешнее
значение и позволяет показать fallback при несовпадении версий. Это разные задачи, а не два
владельца лимитов записи. Отказ должен быть виден автору импорта, чтобы повреждённые данные
можно было заменить, а не бесконечно скрывать.

Цена, покупка и Product Access не являются текстом страницы. Прежняя подстановка сроков самого
дешёвого Offer не задаёт текущие коммерческие правила: они принадлежат
[модели доступа](../product/access-model.md#единая-выдача-доступа-решение-владельца-23102026).
Старые placeholders могут сохраняться в совместимых форматах, не возвращая отменённый тариф.

Цена решения: новое оформление и новый вид блока требуют согласованных изменений backend и web;
источник может менять только данные поддерживаемого словаря. Это ограничение сохраняет единый
вид и проверяемый контракт вместо произвольной страницы каждого автора.
