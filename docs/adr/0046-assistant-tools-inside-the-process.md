# Инструменты Помощника внутри процесса

Владелец принял решение 07.11.2026 в тикете «Помощник: техническое устройство» (#1983).

## Контекст

Помощник читает данные платформы: материалы, программу курса, доступ, прогресс, задания.
Позже админ получит действия с записью, например выдачу доступа. Внешние агенты уже вызывают
те же use case через MCP. Текст ученика и материалов считается недоверенными данными
(ревью #878), а утверждение модели само по себе ничего не доказывает.

## Решение

Модуль `assistant` владеет каталогом инструментов. Каждый инструмент работает как тонкий адаптер
над публичным интерфейсом модуля-владельца. Это та же функция, которую вызывает адаптер MCP.
Модули-владельцы о Помощнике не знают, а `assistant` стоит наверху графа зависимостей
по [ADR 0029](0029-acyclic-module-dependencies.md). Инструменты авторского MCP для разговоров,
оценок и Готовых ответов регистрирует сам `assistant`.

Инструмент объявляет имя, описание, схему входа, роли, вид (чтение или запись) и нужное право
из словаря [ADR 0024](0024-one-access-capability-vocabulary.md). На каждый ход сервер собирает
набор инструментов по Subject сессии. Модель видит только этот набор. Обработчик берёт Account
из контекста сессии, а не из аргументов модели. Use case владельца проверяет права сам ещё раз.

Вызов инструмента записи ничего не меняет. Сервер сохраняет предложенное действие с точными
аргументами и показывает человеку карточку подтверждения. Подтверждение приходит отдельным
запросом браузера с сессией. Текст в чате, даже «да, подтверждаю», подтверждением не считается.
После подтверждения сервер заново проверяет права и выполняет use case с ключом идемпотентности.
Журнал хранит, кто подтвердил действие, с какими аргументами и с каким результатом.

Первая версия содержит только инструменты чтения. Подтверждение и журнал действий строятся вместе
с первым инструментом записи. Оценку ответа ученик ставит обычной мутацией браузера
по [ADR 0012](0012-browser-owned-interactive-mutations.md), без модели.

У Помощника нет канала наружу: нет интернета, отправки сообщений и ссылок, которые пишет модель.
Ссылки на материалы строит сервер. Ссылку на часть, которую поиск в этом ходе не находил,
сервер убирает и отмечает в журнале шагов. Чат показывает ссылки только на домены Inside
и не загружает внешние картинки, потому что адрес картинки тоже может вынести данные.

## Рассмотренные варианты

- **Помощник как клиент нашего MCP-сервера.** Добавляет сетевой переход, сериализацию
  и вторую проверку сессии, а защиты не прибавляет: её дают те же слои.
- **Инструменты Помощника в каждом модуле**, как `registerXTools` для MCP. Описания и правила
  безопасности разошлись бы по 6-8 модулям, хотя evals проверяют их как одну инструкцию.

## Последствия

- Новый инструмент требует публичного интерфейса у владельца. Модуль `assistant`
  импортирует много модулей, но сам никому не нужен, кроме entrypoint.
- Лишний вызов чтения модели запретить нельзя. Он стоит только токенов,
  его частоту показывает журнал шагов и проверяют evals.
