# Перерисовка Telegram-кнопки в Safari — #391

Исправление заменяет Grid на Flexbox только в контейнере действия. Высота 52 px,
центрирование индикатора, ширина кнопки, шрифт, анимация и поведение входа сохраняются.

## Подтверждённый дефект

Владелец сообщил: в Safari и Яндекс Браузере на iPhone видны только фрагменты кнопки;
удержание и выделение текста восстанавливают изображение. После сетевого исправления
#387 загрузка страницы нормализовалась, но этот дефект сохранился.

7 сентября 2026 года тот же рисунок воспроизведён в **нативном Safari 26.5.2** на macOS:
окно шириной 718 px, масштаб страницы 150%, мобильный breakpoint активен. Локальный
HTTP-сервер отдавал точные `telegramSignInPage` и `telegramSignInScript` из production
source; `/status` через три секунды возвращал безопасную fixture-ссылку. После перехода
из loading в pending кнопка оставалась обрезанной до взаимодействия. Два reload и
обратный опыт после отмены CSS-изменения повторили дефект.

| Опыт | Результат первого отображения |
|---|---|
| Исходный Grid | Обрезана |
| Grid, анимация индикатора отключена | Обрезана |
| Минимальная страница без Manrope, темы, логотипа и API | Обрезана |
| Только контейнер заменён на Flexbox | Полностью видна |
| Возврат Grid | Снова обрезана |
| Исправленный production source без переопределений | Полностью видна |

[До исправления](../evidence/issue-391/safari-before.jpg) и
[после исправления](../evidence/issue-391/safari-after.jpg) сняты до hover, focus или
выделения кнопки. Внутренние горизонтальные срезы кнопки (x=45…674, y=630 и 680)
на этих снимках дают заполнение синим 22%/0% до и 100%/100% после. DOM-геометрия
сама по себе не обнаруживает этот дефект: размеры уже правильные, ошибается paint.

## Повторение минимального опыта

Из корня репозитория запустить:

```bash
python3 -m http.server 56294 --bind 127.0.0.1 --directory docs/evidence/issue-391
```

В настоящем Safari открыть `http://127.0.0.1:56294/grid-repaint.html`, установить
масштаб 150% и подождать три секунды, не касаясь области кнопки. Затем открыть
тот же адрес с `?layout=flex`. Это автономный диагностический пример без API,
пользовательских данных и перехода в Telegram. Задержка нужна только для опыта;
production-исправление не добавляет таймеров или принудительной перерисовки.

## Проверки и границы доказательства

Playwright Chromium/WebKit проверяют состояния, мобильную и desktop геометрию,
доступность, фокус, polling, timeout и callback в
`apps/web/test/module/telegram-sign-in.test.ts`. В поставляемом Playwright WebKit
исходный paint-дефект не воспроизводился; эти тесты не заменяют нативный опыт выше.
Проверка на iPhone владельца остаётся отдельной приёмкой #382.

Изменение входит в immutable Logto fork `inside.6`. Source/image identity, результат
сборки, проверок и деплоя фиксируются в PR, закрывающем #391. Обновление не меняет
схему базы или протокол авторизации.
