# Перенос Content в production

Инструкция для автора и агента (#805). Выбранная версия оригиналов из Inside Content попадает на
`https://inside.sachkov.dev` тем же путём, что и на локальный стенд: предпросмотр, отпечаток, точное
применение и журнал. Агент выполняет те же команды, поэтому их можно запустить и вручную.

## Как это устроено

- Доверенная цель `production` названа в `tools/authoring/target.mjs`. Её база —
  `https://inside.sachkov.dev/authoring-api`. Edge пропускает туда только backend `/authoring/*`
  ([таблица маршрутов](production-release.md#public-api-routes)). Любой другой адрес инструмент
  отклоняет, а локальные цели по-прежнему принимают только loopback.
- Каждый запрос несёт короткий токен Logto автора: издатель `https://auth.sachkov.dev/oidc`,
  аудитория `https://api.inside.sachkov.dev`. Право `materials:manage` проверяет Platform.
- Токен выдаёт вход в браузере, который выполняется один раз. Refresh token хранится в macOS
  Keychain (служба `inside-authoring`). Секреты не попадают в Git, аргументы команд, журнал,
  предпросмотр и отчёты.
- На production можно писать только через `authoring:release apply` по проверенному предпросмотру.
  Прямой `authoring:sync-local` и `authoring:sync-git-local` к ней не допускаются. Если цель отвечает
  не как `production`, перенос останавливается.
- Материалы переносятся приватными черновиками, пока публикация явно не одобрена
  ([политика публикации](local-development.md#local-obsidian-authoring-preview-468)). Оболочка курса
  выпускается отдельным пакетом `guide-shell` и уроков не касается.

## Разовая подготовка

Это шаги выпуска; они выполняются вместе с первым применением в production (#810).

1. Развернуть выпуск Platform с маршрутом `/authoring-api/authoring/*`.
2. В production Logto создать приложение типа Native с именем `Inside Authoring CLI`:
   - redirect URI `http://127.0.0.1:47823/callback`;
   - включить refresh token и `offline_access`;
   - разрешить ресурс `https://api.inside.sachkov.dev`.

   Если Logto не обновляет токен без scope, как было с учебным клиентом стенда
   ([learner client](local-development.md#ai-engineering-course-acceptance-stand)), добавить ресурсу scope, выдать его роли владельца и
   передавать при входе через `--scope`. Идентификатор приложения не секретен.
3. Убедиться, что у аккаунта владельца есть `materials:manage`
   ([owner bootstrap](production-delivery.md)).

## Вход — один раз

```bash
pnpm authoring:login --target production --client-id CLIENT_ID
```

Откроется браузер. Вход и подтверждение выполняет сам владелец. После этого сессия лежит в
Keychain, и следующие переносы входа не требуют. Выйти можно командой
`pnpm authoring:login --target production --logout`.

## Каждый перенос

Держите один постоянный каталог состояния вне репозитория, например `~/.inside-authoring/production`.
В нём лежат журнал, экспортированные пакеты и предпросмотры. Его нельзя смешивать с каталогом
стенда: инструмент откажется работать с журналом другой цели.

1. Закоммитьте изменения в Inside Content: переносится только закоммиченная версия.
2. Предпросмотр. Команда ничего не пишет на сайт:

   ```bash
   pnpm authoring:release preview --target production \
     --content ../inside-content --guide inside-ai-engineering [--ref COMMIT] \
     --state ~/.inside-authoring/production [--publish SOURCE_ID]... [--publish-all]
   ```

   Вывод показывает коммит, путь к файлу предпросмотра и каждое изменение. Для материалов видны
   `publication`, `publicationChange` и конфликты. Без `--publish` ничего не публикуется.
3. Посмотрите изменения. Если всё верно, примените ровно этот предпросмотр:

   ```bash
   pnpm authoring:release apply --preview PREVIEW_JSON --state ~/.inside-authoring/production
   ```

   Если сайт изменился после предпросмотра, применение останавливается до первой записи. Сначала
   `apply` дописывает незавершённые записи прошлого запуска с их исходными ключами. Если это
   изменило сайт, он попросит новый предпросмотр.
   Повторите предпросмотр. Конфликт `target_not_draft` значит, что материал уже опубликован:
   одобрите его обновление через `--publish` или уберите из переноса.

Готовый пакет, например оболочку `guide-shell`, можно передать через `--package PACKAGE_JSON` вместо
`--content` и `--guide`.

## Короткий путь автора

Для очередного текста новый выпуск приложения не нужен (#806).

1. **Коммит в Content.** Закоммитьте урок в Inside Content.
2. **Перенос черновиком.** Выполните `preview` и `apply` из раздела выше без `--publish`: урок
   попадёт на сайт закрытым черновиком.
3. **Просмотр точной версии.** Откройте `https://inside.sachkov.dev/authoring/materials`, найдите
   урок и нажмите «Предпросмотр». В шапке видны состояние и номер версии: это счётчик сохранений
   урока в Platform. Какой коммит Content перенесён, показывает вывод `preview` из шага 2. Под
   шапкой — место урока в руководстве: «Назад» и «Дальше» листают главу по порядку, «Все материалы
   руководства» раскрывает состав по главам. Гостю и другим аккаунтам эти адреса ничего не
   показывают.
4. **Публикация материала.** Когда урок принят, повторите `preview` с `--publish SOURCE_ID` этого
   урока и примените его. Публикуется только названный материал; остальные остаются черновиками.

Плеер видео работает только у опубликованного урока. В предпросмотре черновика вместо плеера
стоит строка о том, прикреплено ли видео и готово ли оно.

## Сбой и повтор

- Обрыв связи во время применения оставляет запись с неизвестным исходом. Повторите тот же
  `apply`. Журнал отправит её с тем же ключом идемпотентности, и Platform не выполнит её дважды.
  Если за это время сайт изменился, сделайте новый предпросмотр.
- Если прерванный перенос публиковал материал или его практику, следующий запуск продолжит это
  только с тем же `--publish`.
- Если истёк или отозван вход, команда попросит выполнить `pnpm authoring:login` заново. Отказ `401`
  не считается окончательным: после нового входа повтор `apply` отправит ту же запись.
- Запускайте один перенос в production за раз. Logto меняет refresh token при каждом обновлении, и
  два процесса с одной сессией могут отозвать её друг у друга. Тогда нужен новый вход.

## Границы доверия

Проверка «только через проверенный предпросмотр» живёт в инструменте. Сервер проверяет токен и
право `materials:manage`. Refresh token в Keychain может прочитать любой процесс владельца на этом
Mac, в том числе агент. Это принято: устройство владельца открыто его агентам. Отозвать доступ
можно командой `--logout` или завершением сессий в Logto.
