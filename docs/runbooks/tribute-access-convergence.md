# Tribute: подтверждение реестра и перенос доступа

Platform #625 выполняет контракт Workspace #180. Это инструкция для владельческого интерфейса
`/authoring/billing`, его authenticated API и тех же MCP-команд. Она не разрешает production
inventory, включение внешнего источника, выдачу реальных прав, списания или deploy.

## Подтверждение провайдера

Проверено 14.09.2026 по [официальному описанию webhook](https://wiki.tribute.tg/for-content-creators/api-documentation/webhooks)
и [официальному OpenAPI](https://tribute.tg/api/v1/openapi/en). Webhook использует HMAC-SHA256
исходного тела и заголовок `trbt-signature`. Поддерживаемые события — `new_subscription`,
`renewed_subscription`, `cancelled_subscription`; envelope содержит `name`, `created_at`, `sent_at`,
`payload`. Документация не подтверждает event ID, sequence, начало оплаченного периода или гарантии
порядка. `sent_at` не используется как идентификатор события. Cancel останавливает дальнейшее
продление, а не отзывает оплаченный остаток. Trial/gift не считаются подтверждённой оплатой.

Поддерживаемый публичный полный исторический subscriber export не подтверждён: `/subscribers`
помечен `x-internal`. Реализация его не вызывает. Представление подписи в header не подтверждено
credentialed fixture: encoding необходимо проверить отдельно. Синтетический HMAC hex в локальном
тесте не доказывает совместимость реального аккаунта Tribute.

## Настройка источника

В разделе «Перенос доступа из Tribute» создайте стабильное обозначение источника, укажите
подтверждённый внешний subscription ID, доступный для назначения тариф и причину решения.
Временный режим требует отдельной конечной даты разрешения. Членство в смешанном чате,
скриншот, username и сумма не подтверждают покупку или срок. Пауза источника запрещает новые
назначения; прежние подтверждённые периоды не отзываются.

Для отдельной ссылки активации создайте правило с режимом «Подтверждённый реестр Tribute на
Platform» и этим обозначением источника. Код `a_<code>` не содержит получателя или срока.
Course-ссылка остаётся отдельной и сохраняет бессрочное назначение без списания.
[Portable protocol](../contracts/subscription-activation-v1/protocol.md) определяет точные сообщения,
привязку аккаунта и восстановление ответа. Telegram не принимает решения об оплаченном периоде.

## Импорт

Скачайте CSV-шаблон в интерфейсе. Максимум — 100 строк и 256 КБ в одной сверке. CSV поддерживает
кавычки, запятые внутри ячеек и переводы строк. Заголовки и порядок обязательны:

| Поле | Что подтверждает оператор |
|---|---|
| rowRef / policyRef | Стабильная строка и разрешённый источник |
| subscriptionId | Точное внешнее subscription ID |
| identityRef / telegramUserId | Проверенное сопоставление непрозрачной identity и внешнего получателя; не username |
| verificationRef / checkedAt | Основание проверки и время её выполнения |
| mode | `confirmed_period` либо отдельно одобренный `temporary_membership` |
| startsAt / endsAt | Явные границы в UTC, например `2030-01-01T00:00:00.000Z`; конец обязателен для выдачи |
| renewal | `unknown`, `enabled` или подтверждённое `stopped` |
| expectedRevision | `0` для нового источника, текущая версия для обновления |
| reason | Причина назначения или изменения |

Пустые identity/границы допустимы только для preview: результат требует разбора и не выдаёт прав.
Preview показывает новый, сопоставленный, ожидающий Account, неоднозначный источник, неизвестный
срок и конфликт. Он фиксирует источник, тариф, Enrollment и точную binding revision. Дубликаты
любой стороны сопоставления внутри файла запрещены. Сокращение прежнего срока видно отдельно.
Выберите только проверенные строки. Через десять минут или после изменения состояния нужен
новый preview. Платёж и Account импорт не создаёт.

Неразобранные строки сохраняются после истечения preview и удерживают gate переключения.
Загрузите исправленную сверку; прежние оставшиеся строки закройте отдельным решением с причиной.
Это не меняет уже выданные права. В списках доступна постраничная навигация; метрики учитывают весь
реестр. Не трактуйте первую страницу как полный список.

Если ответ применения потерян, используйте «Восстановить результат применения» в той же вкладке.
В session storage сохраняются только operationId/previewRef/выбранные rowRef. Повтор сначала читает
неизменяемый receipt; он не создаёт повторного назначения. Закрытие вкладки удаляет браузерную
подсказку, но не серверный audit: повторите исходную команду `tribute.apply` с её operationId через
owner API/MCP. Не создавайте новую операцию, пока исходный результат не установлен.

Прежние Tribute-записи без registry state показаны отдельно в «Прежние источники без подтверждённого периода». Для них подтвердите policy, identity и даты в CSV и укажите текущую `expectedRevision`: импорт обогатит ту же запись, сохранив её идентификатор. Старое evidence не превращается в подтверждённую оплату. Новое сохранение Tribute через прежнюю общую форму источников запрещено.

Временное основание создаётся только через подтверждённую аудиторию import. Обычное назначение или смена срока подтверждённого периода не позволяют создать `temporary_membership`. Расширение состава сохраняет приостановку и фактическую границу свежести исходных grants.

Pending источник автоматически сопоставляется после verified linking. Billing worker выполняет
ограниченную пачку из 50 записей в минуту, повторяет неподтверждённые записи и не переводит
источник на другой Account. Временная ошибка linking не означает отсутствие аккаунта.

## События и спорные записи

Endpoint `POST /integrations/tribute/v1/webhook` закрыт собственной проверкой подписи и всегда
private/no-store. Без `TRIBUTE_API_KEY` и явно проверенного `TRIBUTE_SIGNATURE_ENCODING` он
возвращает unavailable. Частичная конфигурация не запускается. Переменные принадлежат серверу;
не копируйте ключ в браузер, CSV, payload, лог или Telegram activation credential.

После проверки исходных bytes inbox фиксирует digest, документ и семантический fingerprint до ACK.
Одинаковый retry не создаёт новый период. Неизвестная schema/source/identity, missing paid type,
неоднозначный порядок или конфликт сохраняются без выдачи. Подтверждённое продление использует
явный внешний конец; отсутствующее начальное подтверждение не заменяется расчётом по цене.

Ежедневно назначенный ответственный сверяет неразобранные события и давно не проверенные
действующие источники с поддерживаемым кабинетом/источником. После подтверждения используйте
повторную проверку. Ошибочную конфликтующую запись отклоняйте явно с причиной и текущей revision;
отклонённая запись остаётся в audit и обычный retry её не оживляет. Applied событие нельзя
«отклонить» ради неявного отзыва прав. Исправление срока проходит новым preview, отзыв и
восстановление — отдельным решением по источнику. История истёкших/отозванных источников не
требует ежедневного продления проверки ради нулевой метрики.

Temporary evidence действует максимум пять минут и никогда не дольше утверждённого срока.
Истёкшее/недоступное подтверждение закрывает именно временное основание; свежий member может
вернуть только непрерванный источник. Подтверждённый left/kicked фиксирует source_ended: join,
покупка Guide, обычный webhook или повтор импорта его не восстанавливают. Новое подтверждение
периода либо явное решение владельца сохраняет один исходный Enrollment. Переход на
confirmed_period отключает legacy bridge атомарно. Независимые Guide/course основания сохраняются.

## Локальная проверка и запуск

Используйте pinned Node из `.node-version`, isolated PostgreSQL и внешние doubles. Полная матрица
и точный статус находятся в [aggregate acceptance](../verification/subscription-access-convergence.md).
Focused commands из корня репозитория:

```bash
pnpm --filter @inside/backend test:integration tribute-sources.test.ts subscription-activation.test.ts
pnpm --filter @inside/backend test subscription-contract-corpus.test.ts
pnpm --filter @inside/web test test/module/tribute-import.test.ts
pnpm api:check
pnpm mcp:check
pnpm docs:check
```

Перед миграцией 0064 сохраните backup выбранной локальной БД. Она добавляет source facts,
политику, durable inbox/review и режим activation rule; сама миграция не импортирует участников,
не включает продажу и не назначает реальные права. Для rollback сохраняйте history и receipts;
не удаляйте их ради повтора. Проверка backup/restore входит в сценарий 31.

Внешние gates остаются открытыми: полнота реестра и реальные периоды, credentialed подпись/feed,
права и управление двумя ботами, ответственный за reconciliation, доказанная остановка старых
Tribute renewal/retries, новое согласие на Platform recurring, cutover/rollback #150 и legal #179.
Наличие кода или локальный PASS не является разрешением этих действий. Отмена renewal сохраняет
оплаченный остаток; отсутствие согласия и подтверждения прекращения старых списаний запрещает
новый recurring. Публичная продажа подписки этой задачей не включается.
