# #301 — шаги как часть карточки

Вопрос владельца: заменить отдельные плашки последовательности оформлением внутри карточек
и сравнить варианты на одной смешанной серии. Это throwaway prototype, не production change.

База — Platform PR #300, commit `18971486e2c3011f164048858e508ad6c29f6ced`.
Выбранного победителя пока нет. Сохранение отметок и общий порядок не менялись.

## Варианты

Последнее уточнение владельца: сравнить способы показать связь последовательных текстовых
гайдов среди вставленных видео, сохраняя сами карточки. Разные бейджи не отвечали на вопрос.
Структурные переделки карточек и прежние mark-only варианты отклонены.

Все варианты используют исходный MaterialCard row: обложки, заголовки, формат/тема, внешние
номера и порядок списка. Меняется слой связей. Вариант B добавляет ссылки в слот отметки;
на узком экране это может увеличить высоту карточки. Карточки без шага не изменены.

- A — пунктирная линия соединяет отмеченные гайды через промежуточные видео/заметки.
  Точки есть только у связанных шагов. Сама цепочка остаётся частью общего списка.
- B — ссылки на предыдущий/следующий шаг внутри отметки гайда. Клик прокручивает этот же
  список к связанному гайду; название адресата видно в tooltip. Reader navigation не меняется.
- C — компактная схема инструкции перед списком. Каждый шаг связан якорем с исходной
  карточкой; между шагами обозначены и доступны ссылки на вставленные видео/заметки.

Связь определяется explicit stepGroup membership, а не автоматически форматом «Гайд».
В демо одна цепочка из трёх гайдов на позициях 2, 5, 6. Общий порядок всех шести материалов
сохраняется, main/optional roles и дополнительные Reader routes не вводятся.

Варианты используют опубликованные данные существующей Series и штатную оболочку. API, auth
и ссылки Reader сохранены. Переключатель меняет только `variant` query, доступен кнопками
и стрелками клавиатуры; ввод текста и модификаторы клавиатуры не перехватываются.
Сравнение и переключатель включены только вне production. При переносе победителя удалить
prototype-компоненты и переключатель; не переносить временную ветку целиком в main.

## Запуск

При работающем локальном API на 3001, с Node/pnpm версий проекта:

```bash
pnpm prototype:series-cards
```

URL: http://127.0.0.1:3215/series/demo-series-release?variant=A
(также B и C). Существующий preview на 3000 и Compose не пересобирались и не останавливались.
Отдельный host Web на 3215 использует read-only published API; новых фикстур/записей нет.

## Проверено

- Ручной Chrome/CUA просмотр A/B/C, переключение ArrowRight с изменением URL; B: переход
  с первого гайда к шагу 2; C: переход из схемы к вставленному видео, оставаясь в списке.
- Desktop 1440×1000 и mobile 390×844: Playwright CLI captures A/B/C; каждый вариант содержит
  все шесть материалов в исходном порядке и три отметки внутри карточек. A показывает
  непрерывную связь, C — обзор цепочки. В B ссылки компактные, названия адресатов — в tooltip.
- Web typecheck прошёл. Полный тестовый/CI прогон для throwaway UI не запускался, по prototype
  workflow. Эта проверка не заменяет production visual acceptance будущего выбранного варианта.

PNG рядом. В full-page captures плавающий переключатель и мобильная навигация остаются на
высоте исходного viewport; при прокрутке пользователь может увидеть перекрытую ими область.
