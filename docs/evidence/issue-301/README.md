# #301 — шаги как часть карточки

Вопрос владельца: заменить отдельные плашки последовательности оформлением внутри карточек
и сравнить варианты на одной смешанной серии. Это throwaway prototype, не production change.

База — Platform PR #300, commit `18971486e2c3011f164048858e508ad6c29f6ced`.
Выбранного победителя пока нет. Сохранение отметок и общий порядок не менялись.

## Варианты

- A — обложка и заголовок, компактная отметка шага под заголовком внутри карточки.
- B — номер шага встроен в левую часть карточки, обложку заменяет номер или значок формата.
- C — компактные текстовые карточки без обложек; шаг справа на desktop и ниже на mobile.

Варианты используют опубликованные данные существующей Series и штатную оболочку. API, auth
и ссылки Reader сохранены. Переключатель меняет только `variant` query, доступен кнопками
и стрелками клавиатуры; ввод текста и модификаторы клавиатуры не перехватываются.
Сравнение и переключатель включены только вне production. При переносе победителя удалить
prototype-компоненты и переключатель; не переносить временную ветку целиком в main.

## Запуск

При работающем локальном API на 3001, с Node/pnpm версий проекта:

```bash
pnpm prototype:series-cards
```

URL: http://127.0.0.1:3215/series/demo-series-release?variant=A
(также B и C). Существующий preview на 3000 и Compose не пересобирались и не останавливались.
Отдельный host Web на 3215 использует read-only published API; новых фикстур/записей нет.

## Проверено

- Ручной Chrome/CUA просмотр A/B/C, переключение кнопкой и ArrowRight с изменением URL.
- Desktop 1440×1000 и mobile 390×844: Playwright CLI captures A/B/C; каждый вариант содержит
  все шесть материалов в исходном порядке и три отметки внутри карточек.
- Web typecheck прошёл. Полный тестовый/CI прогон для throwaway UI не запускался, по prototype
  workflow. Эта проверка не заменяет production visual acceptance будущего выбранного варианта.

PNG рядом. В full-page captures плавающий переключатель и мобильная навигация остаются на
высоте исходного viewport; при прокрутке пользователь может увидеть перекрытую ими область.
