# #595 — команда в одной вкладке обновляет вторую открытую

Снимки сняты сквозными проверками `apps/web/test/e2e/account-cabinet.spec.ts` на 1440 и 390, с
подменёнными маршрутами BFF. На каждом снимке — **первая** вкладка: она открыта заранее, а команду
выполняет вторая вкладка того же браузера. Между снимками «до» и «после» первая вкладка не
перезагружалась.

| Файл | Что показывает |
| --- | --- |
| `subscription-before-*.png` | Раздел «Подписка» до команды: продление действует, предлагается «Отменить продление» |
| `subscription-after-*.png` | Тот же раздел после отмены продления во второй вкладке: «Продление отменено», предлагается «Возобновить списания» |
| `notifications-before-*.png` | Раздел «Уведомления» до сохранения: Email не выбран |
| `notifications-after-*.png` | Тот же раздел после сохранения выбора Email во второй вкладке: Email выбран |
| `notifications-refusal-*.png` | Отказ по расхождению редакции при сохранении настроек: «Данные изменились. Повторите действие.» |

Отказ по расхождению редакции — решение владельца от 15.09.2026, как в #601. Прежний текст
отправлял искать другую вкладку, хотя после этой задачи вкладки одного браузера сходятся сами;
расхождение остаётся возможным только между устройствами. Проверка «отказ по расхождению редакции
настроек показывает текст из источника отказов» подменяет ответ BFF
`/api/account/notifications/preferences/change` отказом и сверяет показанный текст с
`notificationErrorMessage("revision_conflict")`, а не с копией строки. На снимке телефона отказ
прокручен в центр экрана, чтобы его не закрывал нижний док.

Блок сообщества вверху раздела «Подписка» в разных снимках выглядит по-разному («Проверяем
возможность вступления…» или кнопка повтора): в проверке его маршрут не подменён, и к механизму
объявления это не относится.

Граница: объявление доходит только до вкладок одного браузера. Второе устройство так не
обновится — для этого нужен серверный толчок, в эту задачу он не входит.

Воспроизведение: временно добавить `page.screenshot({ path: evidencePath("issue-595", …) })` в
проверки «отмена продления меняет раздел «Подписка», открытый второй поверхностью» и «сохранённый
выбор каналов виден во второй открытой поверхности», затем из `apps/web` запустить
`UPDATE_EVIDENCE=issue-595 PLAYWRIGHT_PORT=<порт> pnpm exec playwright test test/e2e/account-cabinet.spec.ts -g "открытый второй поверхностью|второй открытой поверхности" --workers=1`.
