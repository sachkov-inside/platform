# Доступ к продуктам без подписок

Решение владельца от 20.10.2026: [ADR 0037](../../adr/0037-products-without-subscriptions.md).
Задача: убрать текущую продажу подписок и её денежные сценарии, показать доступ к конкретным
продуктам и упростить кабинет. Будущие подписки отделены от продуктов.

## Проверенные сценарии

- Подтверждения терминала и погашённое приглашение не включают продажу подписки в текущем runtime.
- Нет новой подписочной покупки, возобновления, оплачиваемой смены, привязки карты или регулярного
  списания. Сверка уже отправленных оплат и история сохраняются.
- Старое приглашение, включая погашённое, больше не предлагает checkout. Новая выдача и повтор
  прежней команды выдачи заблокированы; исторические записи доступны для чтения и отзыва.
- Напоминания о регулярном списании не планируются и отсекаются повторной проверкой перед отправкой.
- Доказанно неотправленные `prepared` попытки закрываются с освобождением reservation; `sent` и
  неизвестные банковские исходы продолжают сверяться без нового Init/Charge.
- Карточка продукта объединяет права и покупки, сохраняет истёкшие, отозванные и запланированные
  назначения, не выдаёт их за текущий доступ. Изменение прав обновляет открытые поверхности.
- Кеш сообщества принадлежит Account. При смене A на B с общим QueryClient ссылка A не показывается
  во время проверки B.
- Условия первого потока AIE проверяет существующий `aie-sales-setup.test.ts`: материалы и
  сообщество бессрочны, поддержка 6 месяцев. Снимки прошлых покупок не переписывались.

## Границы результата

В работающем Telegram provider доступна только существующая группа `primary`. Текущий продукт
можно явно связать с ней или отвязать. Для других реальных групп нужен адресуемый provider/delivery
contract. Код не имитирует поддержку нескольких групп одним произвольным значением настройки.

Работающий общий стенд, production-каталог, исторические назначения и юридические редакции не
изменялись. Если ранее выданный доступ AIE содержит ошибочный срок сообщества, его исправляет
проверенная операция расширения по фактическим данным, с сохранением отзыва и истории.

## Повторный вход для почты

Уточнение владельца от 20.10.2026: действующая сессия не требует нового входа для управления
почтой. Fork `inside.11` сохраняет аутентификацию, first-party client, разрешение поля и OTP,
но убирает дополнительное условие `email` scope для этих собственных Account Center routes.

`scripts/account-email-proof.py` воспроизвёл отказ на прежнем `inside.10`, затем прошёл на
локальном `snapper-logto-email:inside.11`: существующая `openid`-only сессия читает почту, получает
код и привязывает первый адрес. Новый вход по почте сохраняет provider subject. Проверены
чужой/неверный/истёкший код, занятый адрес, повтор, конкуренция, запрет замены credentials,
лимиты отправки/попыток, anonymous/third-party и Account Center ReadOnly/disabled.

Из-за TLS timeout реестра полный Dockerfile локально не собрался. Для этого proof новый модуль
скомпилирован с `npm run check` и `tsup` поверх имеющегося `inside.10`; исходный модуль образа
перед заменой побайтово совпал с базовой версией Git. Это функциональная проверка настоящего
Logto, не доказательство полной чистой сборки. Поставка требует нового образа `inside.11`.
