# #602 — контролы блока стоят там же, где стояли

Снимки и замеры сняты в Storybook, в настоящей оболочке редактора: история «Страницы/Редактор/Материал
и предпросмотр» на фикстуре `materialAuthoringPresentation`, окно 1440 и 390. `before` — код
редактора из `origin/main` (`ee4e1a87`), `after` — эта ветка (`ade20a99`). Все числа взяты из
`measurements.json`, снятого тем же прогоном, что и снимки.

## Кнопка и панель на тех же местах

Кнопка «Добавить блок»: разница между верхом кнопки и верхом блока, у которого она должна стоять.
Панель форматирования: разница между верхом панели и местом, которое задаёт правило контролов, —
на 46 пикселей выше начала выделения, но не выше поверхности редактора.

| Замер, пиксели | До, 1440 | После, 1440 | До, 390 | После, 390 |
| --- | --- | --- | --- | --- |
| Курсор в абзаце | 0 | 0 | 0 | 0 |
| После набора 10 знаков в том же абзаце | 0 | 0 | 0 | 0 |
| После Enter, у нового абзаца | 0 | 0 | 0 | 0 |
| Указатель над первым абзацем | 0 | 0 | 0 | 0 |
| Панель форматирования над выделением | 0 | 0 | 0 | 0 |

Каждое положение снято после двух кадров, то есть уже нарисованным. Отдельно не измерялось, в
каком кадре контролы встают: до правки они применялись синхронно в обработчике транзакции, после —
замером в `requestAnimationFrame` через `flushSync`, до отрисовки того же кадра.

## Что роняет проверку

Проверка — `expectBlockControlsWithoutKeystrokeCost` в
`apps/web/src/workshop/material-authoring.stories.tsx`, истории «Редактор · контролы блока» и
«Редактор · контролы блока, мобильный». Истории выполняются в `pnpm test`, то есть в `pnpm check` и
CI. Команда прогона:

```
pnpm --filter @inside/web exec vitest run --config vitest.config.mts --project=storybook \
  src/workshop/material-authoring.stories.tsx -t "контролы блока"
```
