Это запись исследования для Home22, план 3.6, и Platform #2266. Исполняемый договор принадлежит [руководству CI](../runbooks/continuous-integration.md#documentation-evidence-in-the-merge-queue). Эта запись не разрешает пропускать дополнительные проверки.

Установка механизма завершена в [PR2270](https://github.com/sachkov-inside/platform/pull/2270), merged source `ab6766ce6a85d7f969e95d5be82b90661c9c0195`. Её [настоящая очередь43965759081](https://github.com/sachkov-inside/platform/actions/runs/43965759081) проверила полный план обеих приложений:28 успешных задач и четыре исключённых, все десять требуемых видов покрытия подтверждены. Это доказательство установки, а измерение отдельного документационного пути следует ниже.

## Что показал одиночный повтор CI

В установочном PR2270 запуск [43958733200](https://github.com/sachkov-inside/platform/actions/runs/43958733200) сначала отклонил мобильный Home pin. После записи отдельной Issue2277 выполнен один разрешённый повтор отказавших задач. Итог второй попытки успешен; причина исходного отказа осталась отдельным вопросом.

API выдал новые job IDs и номер попытки даже сохранённым успешным результатам. При этом их времена начала и завершения остались прежними. Подсчитывать их как новые исполнения было бы ошибкой.

Всего во второй попытке 32 записи, из них 25 сохранённых успешных результатов, четыре исключённых результата и три новых исполнения. Это штатное сохранение результатов GitHub при повторе отказавших задач. Проверяемое в этой работе повторное использование документационного результата рассматривается отдельно. Номер попытки в записи самого производителя связывает результат с его реальным исполнением.

## Почему нужна отдельная проверка документации

Установка механизма меняет workflow и скрипты, поэтому сама проходит полный набор проверок приложений. Последующий PR с обычным текстом сохраняет уже принятый исполняемый код. Он позволяет проверить настоящее равенство входов между PR и очередью, не подменяя проверку приложений результатом короткого сценария.

Этот PR служит такой проверкой. Ссылки на фактические запуски, их исходы и решения механизма сохраняются в описании PR после исполнения. Заранее успешный исход не предполагается. Отличающееся окружение, дерево или неполное доказательство должны привести к обычному запуску документационных проверок.

## Как читать измерение

Нужно различать выполненную задачу CI и повторно используемый результат проверок внутри неё. Задача документации всё равно выполняет подготовку окружения и проверку доказательства. Отдельно учитываются время настоящих проверок, время чтения доказательств и полное время задачи по данным GitHub.

Продолжительность прежней проверки сама по себе не равна экономии. Проверки документации короткие, а чтение API и подготовка среды тоже занимают время. Вывод об ускорении требует наблюдаемых измерений. Результаты этого узкого пути не доказывают возможность безопасного повторного использования Docker, браузеров, баз данных или полного покрытия приложений.
