# Обновление Caddy и проверка HTTP/3

2026-09-08, [#399](https://github.com/sachkov-inside/platform/issues/399).
Владелец разрешил обновление и проверки после [исследования #397](https://github.com/sachkov-inside/platform/issues/397).

## Результат

На production установлен официальный пакет Caddy 2.11.4 вместо Ubuntu 2.6.2-14.
Версия закреплена в apt preferences; её источник и SHA-256 —
[`install-caddy.sh`](../../infra/production/host/install-caddy.sh).
Текущий Caddyfile сохраняет `h1 h2`, маршруты приложения не изменены.

Серверный дефект после reload устранён. Отдельная проверка показала, что текущий
VPN-маршрут не устанавливает QUIC-соединение даже с исправленным сервером. Поэтому
публичный H3 после ограниченного опыта снова выключен. Обновление исправляет код
сервера, а H2 сохраняет совместимость с наблюдаемым сетевым ограничением.

## Проверки

| Опыт | Результат |
|---|---|
| Установленный `/usr/bin/caddy`, loopback, свежий Python-процесс на запрос | 20/20 HTTP 200; H2 и H3 работают после двух reload, включая первые запросы |
| Публичный H3, прямой маршрут через `en0` | Три серии по 12 запросов: 36/36 HTTP 200; принудительный H3 действительно `V3`, H2 — `V2_0` |
| Прямой H3 на Telegram-странице | 63 мс в первой серии, 55 мс после второго повторного reload; прежнего зависания с 0 bytes нет |
| Текущий системный/VPN-маршрут, принудительный H3 | 4/4 connection timeout на пятисекундном лимите клиента |
| Тот же маршрут, H2 и H3 с разрешённым fallback | 8/8 HTTP 200; fallback фактически `V2_0`, примерно 1.4–1.5 с |
| Шесть Globalping точек в России, HTTPS GET Telegram-страницы | 6/6 HTTP 200, 69–282 мс; это проверка HTTPS, не HTTP/3 |

Все публичные серии проверяли главную Inside, Logto discovery, Telegram-страницу и
её script. Клиент `curl_cffi==0.16.3` выводил фактический протокол, статус, bytes и время;
проверка TLS включена. Прямой опыт обходил VPN через `en0`; системный маршрут сохранял
сетевые настройки устройства. Таймауты обозначают пределы теста, не длительность
всех возможных ожиданий браузера.

В первом обновлении автоматический откат сработал из-за различия имён `group` в JSON,
который создают разные версии Caddy. Сравнение `adapt` показало только два изменения
имени той же группы. Проверка теперь нормализует имена с сохранением равенства групп;
маршруты, их порядок, условия и upstream не игнорируются. Повторное обновление принято.

## Границы и эксплуатация

Это не доказательство работы в каждой сети или на iPhone владельца. Успешный TLS,
HTTP 200 и видимая страница сами по себе не доказывают завершённый вход через Telegram.
Сообщения боту и подтверждение реального аккаунта в этих опытах не выполнялись.
Прямое открытие `/api/inside-telegram` без начатой авторизации закономерно показывает
ошибку отсутствующего контекста; браузерная приёмка должна начинаться с кнопки «Войти».

Пакет и Caddyfile для отката находятся в root-only каталоге
`/var/lib/inside/deployments/caddy-399-backup`. Порядок следующего обновления и отката
принадлежит [production runbook](../runbooks/production-foundation.md#обновление-пакета-caddy-на-работающем-сервере).
Полные локальные артефакты сохраняются в `inside/platform/issue-399-20260908`.
