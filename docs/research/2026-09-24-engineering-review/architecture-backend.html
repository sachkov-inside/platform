Problem. Ошибки Prisma, хранилища и провайдеров превращаются в dependency_unavailable без записи причины. Nest Logger используется 0 раз, логгер Fastify выключен, request id нет.

Solution. Один module reportDependencyFailure(scope, error) за seam логгера. Он классифицирует ошибку, пишет структурную строку и возвращает вариант union. Сто семьдесят шесть catch {} заменяются вызовом этого module.

  • leverage: одно interface на 176 мест вызова
  • locality: классификация ошибок в одном месте
  • тест: адаптер логгера в памяти проверяет причину
  • Сбой worker при старте сохраняет stack

Problem. Каждый entrypoint повторяет четыре вызова pg-boss. Политика повторов разная без имени: billing — 0 повторов, очистка — 5 с backoff.

Solution. runWorker принимает описание sweep и сам создаёт очередь, расписание, запуск и запись результата.

  • interface сужается до описания sweep
  • Политика повторов получает имя
  • Минус ~150 строк в entrypoints
  • тест: sweep проверяется без pg-boss

Top recommendation

1. Отказ зависимости как один module с записью причины

176 мест теряют причину сбоя, а Platform уходит в платёжный запуск: без этого module каждый инцидент billing, notifications или хранилища расследуется вслепую. Изменение не трогает ни одно ADR, даёт наибольший leverage и готовит почву для кандидатов 3 и 6. Следом — кандидат 2: он закрывает реальный риск целостности в самом горячем месте, save-material.
