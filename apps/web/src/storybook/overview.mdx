# Каталог интерфейса Platform

Здесь собран текущий интерфейс продукта. Страницы и компоненты используют тот же код,
шрифты и тему, что и приложение. Данные демонстрационные: оплаты, выдача доступа и
публикация материалов не выполняются.

Для работы над страницей начинайте с **Pages**. Для изменения одного элемента переходите
в **Components**, для целого блока внутри страницы, например вкладки продукта, в **Patterns**.
В **Pages / Product / Landing** находятся разные действующие виды витрины, а в
**Pages / Product / Programme** программа, её загрузка и подключение ученика.
Это состояния одних маршрутов, а не дополнительные разделы сайта.

**Pages / Account / Cabinet** показывает личный кабинет с загрузкой данных.
**Patterns / Account / Cabinet states** изолирует его состояния: загрузку, ошибку,
истёкшую сессию и журнал документов. Так можно проверить нужный случай без повторной страницы.

## Состояния и размеры

Именованная история описывает отдельный сценарий: готовые данные, пустой список,
ошибку, отсутствие доступа или результат действия. Варианты mobile и desktop проверяют
один сценарий при разной ширине. Controls меняют поддерживаемые свойства компонента.
Вкладка Docs объясняет назначение, а Interactions показывает проверяемые действия.

Оболочка, отступы и доступные действия должны совпадать с приложением. Обёртки страниц
задаёт `src/storybook/story-environment`. Прототипы и предыдущие варианты остаются на
своих ветках `prototype/*` и в истории Git. Локальный выбор тестового аккаунта и
отключённая форма почты для входа не входят в текущий каталог продукта.

## Карта маршрутов

Карта берётся из `catalog.json`. Модульная проверка сравнивает её с фактическими
`app/**/page.tsx` и проверяет наличие историй. Перенаправления и снятые адреса перечислены
отдельно, чтобы их не принимать за недостающие страницы.

## Обновление каталога

При изменении страницы или общего элемента обновляйте его истории в том же PR.
Удаление поверхности включает удаление её историй и неиспользуемых фикстур.
Новый маршрут добавляется в карту с историей либо конкретной причиной исключения.
Сохраняйте существующий `id` при перемещении истории между разделами: на него ссылаются
проверки и сохранённые свидетельства ревью.

Перед передачей изменений запустите `pnpm test:storybook` и `pnpm build:storybook`.
Проверьте затронутые страницы при ширине 390 и 1440, включая основные действия.
Production-модули не импортируют истории, фикстуры или `src/storybook`.
