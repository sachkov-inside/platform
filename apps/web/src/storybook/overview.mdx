# Platform UI laboratory

Storybook is the executable interface to the Platform UI system for people and agents. Start with
the smallest layer that answers the question at hand:

1. **Foundations** explain the visual language and its provenance.
2. **Components** document bounded controls, states, props, and accessible behavior.
3. **Patterns** show components collaborating around a reusable product responsibility.
4. **Pages** preserve responsive product proofs and realistic user flows.

## Story contract

Each story captures one meaningful use case, explains why it exists, uses realistic Russian
product content, and asserts its critical behavior in a `play` test. Controls are for exploring
supported props; they are not a substitute for named states. Responsive page proofs start at
320 × 568 and keep the same information hierarchy on desktop.

A story shows the production module in its production environment: a page-level story wraps it in
the shell of its route, a component story uses the containers its real page gives it, and neither
re-creates page markup of its own. `src/workshop/story-environment` owns those wrappers. When a
story and the application disagree, the application is the reference and the story changes.

## Agent workflow

When Storybook is running, inspect the catalog and rendered Docs at `http://localhost:6006`. Read
the component documentation before editing UI, preview every changed story, and run
`pnpm test:storybook` and `pnpm build:storybook` before handing work back. JSDoc, story
descriptions, controls, and hierarchy should make intent recoverable without opening
implementation files.
