# Prototype #967: раздел «Сдачи»

Ветка `prototype/967-learning-submissions` сохраняет throwaway proof. Она не мержится в `main`.
Production-маршрут и его временный модуль #948 остаются прежними.

Вопрос приёмки: какая структура помогает автору выбрать сдачу, прочитать полный отчёт и оставить отзыв?
Все варианты используют существующий `TaskSubmissions` и принятую авторскую оболочку.
Fixtures синтетические. Фильтры и отзыв работают в памяти; сетевых записей нет.

| Вариант | Структура | Что проверить |
| --- | --- | --- |
| A — очередь и отчёт | Список слева, выбранная сдача справа; на телефоне последовательно | Удобно ли переходить между сдачами? |
| B — таблица и отчёт | Компактная таблица, выбранная сдача ниже | Достаточно ли данных для выбора? На телефоне таблица прокручивается внутри своего блока. |
| C — лента сдач | Все сдачи и отчёты идут последовательно | Помогает ли общий просмотр или создаёт лишнюю прокрутку? |

Storybook: `Prototypes/967/Сдачи`, история `Comparison`. Параметр `?variant=A|B|C` закрепляет вариант.
Нижний переключатель и клавиши Left/Right меняют вариант. Поля ввода сохраняют свои клавиши.
Истории `Loading`, `Empty`, `Error`, `Denied` показывают состояния страницы.
Ошибка позволяет повторить загрузку в памяти prototype.

Запуск из корня текущего worktree после установки pinned dependencies и `pnpm build:generated`:

```sh
pnpm storybook --port 6017 --no-open
```

Порт 6017 закреплён за #967. Старт и сборка ожидают явной передачи общего тяжёлого слота.
Preview имеет отдельного владельца процесса; длительная приёмка не удерживает heavy wrapper.

Proof после запуска, из `apps/web`:

```sh
node scripts/task-submissions-prototype-proof.mjs <artifact-directory> http://127.0.0.1:6017 <exact-proof-commit>
```

Скрипт проверяет 390/1440, внешний горизонтальный overflow, serious/critical нарушения доступности,
полный текст отчёта, работу фильтра и сохранение отзыва в памяти. Снимки и `proof.json` сохраняются вне Source.
До запуска эти проверки не считаются выполненными. В отчёте указываются реальные exits и exact commit.

Владелец принимает точный proof commit и вариант. Production UI начинается после его visual GO.
Production получает новую ветку от актуального `main`, реальные адаптеры и отдельную визуальную приёмку.
