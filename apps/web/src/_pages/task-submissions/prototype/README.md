# Прототип «Сдачи»

Прототип проверяет, достаточно ли списка сохранённых сдач и отдельной страницы, чтобы автор быстро понял результат самопроверки.
Владелец принял исправленный вариант A на коде `7c70aa84`.
Владелец согласовал прототип на вымышленных данных, или дал `proof GO`. После подключения к реальным данным требуется отдельное согласование production UI, или `production visual GO`.

Ветка `prototype/submissions-minimal-v2` создана от `f5a6d87597d0d3b5408d6bf25fc474c41ca8d06b`.
Прототип остаётся на этой ветке; merge в `main` и deploy не выполнялись.
[Задача #854](https://github.com/sachkov-inside/platform/issues/854) переходит к подключению принятого интерфейса к реальным сдачам.

## Решения принятого прототипа

- Каждая сохранённая сдача занимает отдельную строку и открывает отдельную страницу. Неуспешные попытки сохраняются в списке.
- Страница показывает имя ученика, username и ссылку Telegram. Если Telegram не подключён, страница прямо сообщает об этом.
- В начале страницы стоят итог самопроверки и короткое резюме агента ученика. Итог отражает выводы отчёта; в макете данные заданы примерами.
- Страница показывает номер первой успешной сохранённой самопроверки, если она есть, и историю сохранённых проверок ученика по заданию.
- Номер попытки относится к сохранённой самопроверке. Сдача через форму без отчёта агента показана без номера.
- Подробности по критериям, проект и заметка ученика по умолчанию свёрнуты.
- Необязательный комментарий автора по умолчанию свёрнут сразу под итогом самопроверки. После сохранения блок показывает комментарий.

В историю попадают только сохранённые сдачи и проверки. Работа между проверками туда не попадает.
Макет не сохраняет весь диалог ученика с агентом и не гарантирует продолжение диалога в новой сессии.

| Вариант | Что показывает | Зачем сравниваем |
| --- | --- | --- |
| A, список | Строки сдач, новые сверху | Принятая основа для просмотра и открытия сдачи |
| B, таблица | Те же сдачи в колонках; на телефоне строки | Позволяет сравнить результат, номер и дату между сдачами |
| C, по датам | Сдачи собраны по дням; история выше подробностей | Выделяет последовательность сдач во времени |

## Внешний вид и источники

Макет продолжает существующий мир `Soft Technical Workshop`, описанный в [DESIGN.md](../../../../DESIGN.md).
Тёплый светлый фон оставляет место содержанию. Тонкие разделители собирают строки списка без декоративных карточек.
Manrope используется для текста, а оранжевый акцент помогает заметить действие и состояние.
На телефоне сохраняется порядок сведений; таблица становится списком.
Продуктовые ограничения задаёт [PRODUCT.md](../../../../PRODUCT.md). Этот README фиксирует решения принятого прототипа.

Владелец сообщил, что раскрытые блоки трудно читать из-за горизонтальных линий и слитного текста.
Правка `7c70aa84` убрала рамки у итога, раскрываемых блоков и критериев. Теперь разделы отделяются свободным местом.
Заголовок критерия и его статус стоят рядом; пояснение начинается ниже отдельным абзацем.
На телефоне статус переносится под заголовок. Текст подробного отчёта имеет размер 16 px и межстрочный интервал 26,4 px.
Заметка ученика получила собственную подпись. Владелец принял обновлённое раскрытое состояние вместе с вариантом A.

- Цвета, скругления и основные шрифты приходят из [globals.css](../../../../app/globals.css).
- Storybook загружает Manrope и JetBrains Mono через [preview.tsx](../../../../.storybook/preview.tsx).
- Существующая [AuthoringShell](../../../widgets/authoring-shell/ui/authoring-shell.client.tsx) обрамляет страницу через [story-environment.tsx](../../../storybook/story-environment.tsx).
- Поведение и примеры живут в [submissions-minimal.client.tsx](submissions-minimal.client.tsx), размеры поверхности в [submissions-minimal.css](submissions-minimal.css), состояния в [stories](submissions-minimal.stories.tsx).

## Запуск и просмотр

Из корня этой ветки с Node.js `26.10.0` и pnpm `11.27.1` выполни одну команду:

```bash
pnpm storybook --port 6127 --ci
```

Открой [список](http://localhost:6127/?path=/story/prototypes-submissions-minimal--list) или [страницу сдачи](http://localhost:6127/?path=/story/prototypes-submissions-minimal--submission).
Для проверки читаемости открой [сдачу с раскрытыми блоками](http://localhost:6127/?path=/story/prototypes-submissions-minimal--expanded-submission).
Переключатель A/B/C работает кнопками со стрелками и клавишами `ArrowLeft`/`ArrowRight` вне полей ввода.
Аргумент `showVariants` включает переключатель явно. У компонента он равен `false` по умолчанию; истории включают его для сравнения.
Аргумент `expanded` раскрывает подробности и комментарий для проверки. Он равен `false` по умолчанию; история `ExpandedSubmission` включает его явно.
Параметры `variant` и `submission` записываются в адрес iframe и переживают перезагрузку этой страницы.

## Ограничения макета

Все имена, username, отчёты, даты и проекты вымышлены. Нажатие ссылки Telegram перехватывается и показывает пояснение.
Комментарий автора хранится только в памяти макета и исчезает после перезагрузки. Ученик его не получает.
Прототип подключён только к Storybook. Backend, production-маршруты и контракты не изменены.

На ширинах 1440 и 390 px горизонтального переполнения нет. После правки все десять историй прошли локальные проверки Storybook и Axe на доступность.
До правки читаемости десять браузерных проверок прошли успешно. Они покрыли переход к сдаче, фокус заголовка, возврат, поиск, фильтр результата и сброс пустого поиска.
Также проверены переход по истории, сохранение комментария в памяти, переключение A/B/C и восстановление варианта после перезагрузки.

После правки отдельно проверены раскрытие стандартных блоков с клавиатуры, сохранение комментария в памяти и возврат к списку.
Вычисленные стили подтвердили размер текста отчёта 16 px, межстрочный интервал 26,4 px и отсутствие рамок у раскрытых блоков и критериев.

Свежее визуальное ревью `impeccable_finish_reviewer_v2` на `7c70aa84` дало `ship` без находок.
Повторное ревью стандартов и соответствия задаче на том же коде завершилось без находок.
Прежний `ship` относился только к переносу комментария. Прежний детектор шрифтов отметил 22 локальных значения в CSS как рекомендации.
Тогда проверка не нашла существенного расхождения с существующим визуальным миром.

Полный `pnpm check` завершился с кодом 0 на `4adc1fa1`, до правки читаемости.
Финальный `pnpm check` на `7c70aa84` завершился с кодом 1.
Единственный сбой произошёл в незатронутом тесте `scripts/local-build-context-smoke.test.mjs:135`.
Тест получил `ENOENT` при чтении временного файла с идентификатором процесса. Финальная полная проверка не зелёная.

Владелец разрешил следующий шаг ответом «продолжи». Задача #854 подключает основу A к реальным сдачам.
После подключения требуется отдельное согласование точного production-интерфейса в Storybook и рабочем маршруте.
