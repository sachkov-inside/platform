# Воронки Telegram

## Назначение и статус

Режим: **Operate**. Подтверждённый автор управляет знакомством, воронками и историей доставки на
`/authoring/communications`. #308 реализует функциональный путь через временный семантический UI
по default path из `docs/agents/frontend-delivery.md`.

Finish review: `ship` только в функциональном семантическом scope. Окончательное визуальное
принятие владельцем, Storybook proof и замена временного модуля принадлежат
[#316](https://github.com/sachkov-inside/platform/issues/316). Маркер #308 → #316 остаётся на
интерфейсе `CommunicationsWorkspace` до этой интеграции. Новых принятых визуальных решений нет.

## Наблюдаемая реализация

Поверхность сохраняет существующий `AuthoringShell`, общие токены из `app/globals.css` и shared
`Button`. Визуальный источник — `DESIGN.md`; этот brief описывает только конкретную поверхность.
Светлый фон, разделители, подписанные поля и компактные группы действий образуют вертикальную
рабочую страницу. Заголовок и сообщение о текущей операции предшествуют списку воронок;
далее идут раскрываемое общее знакомство и выбранный редактор. На узком экране сохраняется тот же
порядок, группы действий переносятся, связанные поля используют доступную ширину.

Production route и Storybook используют один feature-owned компонент с интерфейсом
`CommunicationsActions`; fixtures не становятся production data path.

## Действия и состояния

- Список: загрузка, ошибка с повторной загрузкой, пустое состояние, открытие и создание воронки,
  переход между страницами. Несохранённые правки блокируют переключение.
- Редактор: название, стандартная воронка, непосредственный ответ, отложенные шаги и источники;
  сохранение черновика, отмена правок и загрузка актуального состояния.
- Части сообщений: текст, заготовки Telegram, ссылки, изменение порядка и удаление. Форматированная
  заготовка сохраняется снимком; переход к редактированию без форматирования требует отдельного действия.
- Общее знакомство: создание и сохранение, с объяснением применения к новым получателям.
- Проверка и публикация: Preview показывает изменения и охват без отправки сообщений. Ошибки
  материалов и Series блокируют публикацию; Publish остаётся явным действием автора.
- Управление: пауза, возобновление, архивирование и восстановление на паузе.
- История: состояния частей и попытки доставки, обновление и переход между страницами. Для failed
  и unknown доступны решения владельца; повтор требует подтверждения риска дубля, а при запрошенной
  отмене скрыт.

Операция объявляется через live region, ошибки — через `role="alert"`. Подписанные поля,
fieldset/legend, видимый фокус и текстовые состояния поддерживают работу с клавиатурой.
Ошибки доступа и конфликта показывают нужное действие восстановления, не подменяя application rules.

## Доказательства и следующий gate

`docs/evidence/issue-308/README.md` фиксирует сквозную проверку реального маршрута на desktop
1440×1024 и mobile 390×844, проверку axe, отсутствия горизонтального переполнения и перехода фокуса.
Там же находятся четыре PNG: Storybook и live route на обоих размерах. Снимки покрывают верх страницы;
сценарии дальнейших действий и ошибок проверяются сквозным тестом. Credentials и реальные Telegram
sends в эту browser-проверку не входят; итоговый общий сценарий относится к #310.

#316 должен принять визуальное исполнение и заменить временную реализацию через тот же интерфейс.
