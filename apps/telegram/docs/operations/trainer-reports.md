# Отчёты автора по Тренажёру

Команда `trainer-report` печатает один из двух отчётов по Тренажёру:

- `--questions`: сколько раз ответили на каждый вопрос и какая доля ответов верная;
- `--usage`: сколько людей открыли Тренажёр и сколько ответили на вопросы, по дням и меткам
  источника.

Команда только читает базу бота. В отчётах нет имён, username и идентификаторов Telegram: они
считают людей, но не называют их. Текстов вопросов и вариантов в отчётах тоже нет. Запуск в
production требует разрешения владельца.

## Запуск в production

Переменная `telegram_compose` задаётся как в разделе
[operations-команд](production.md#operations-команды). Контейнер команды видит только сеть базы.

```bash
"${telegram_compose[@]}" --profile operations run --rm -T trainer-report --questions
"${telegram_compose[@]}" --profile operations run --rm -T trainer-report --usage
```

## Запуск локально

Из `apps/telegram`, с `DATABASE_URL` своей базы:

```bash
pnpm owner:trainer-report --questions
pnpm owner:trainer-report --usage
```

## Вывод и коды выхода

Отчёт печатается в стандартный вывод, одна строка JSON на вопрос или на день. Если строк нет,
вывод пустой. Чтобы сохранить отчёт, перенаправьте вывод в файл вне Git.

| Код выхода | Смысл |
| --- | --- |
| 0 | отчёт напечатан |
| 1 | команда вызвана без `--questions` или `--usage`, с лишними аргументами, без `DATABASE_URL`, или база недоступна |

## Отчёт по вопросам

В отчёте есть каждый вопрос, который когда-либо был загружен в Банк, включая снятые с показа и
те, на которые ещё никто не ответил. Строки идут в порядке тем Банка, внутри темы по
идентификатору вопроса.

```json
{"question":"t1-0001","topic":"t1","topicName":"Контекст и промпты","withdrawn":false,"answers":12,"correct":7,"correctShare":0.58}
{"question":"t1-0002","topic":"t1","topicName":"Контекст и промпты","withdrawn":true,"answers":0,"correct":0,"correctShare":null}
```

| Поле | Смысл |
| --- | --- |
| `question` | идентификатор вопроса из файла Банка |
| `topic`, `topicName` | код и название темы вопроса |
| `withdrawn` | `true`, если вопрос снят с показа; ответы на него остаются в отчёте |
| `answers` | число ответов всех людей во всех режимах, вместе с повторными |
| `correct` | число верных ответов; «Не знаю» считается неверным ответом |
| `correctShare` | `correct / answers`, округлено до сотых; `null`, если ответов нет |

Показанный вопрос, на который человек не ответил, в `answers` не входит.

## Отчёт по использованию

Одна строка на каждый день, в который кто-то открыл Тренажёр или ответил на вопрос. Дни считаются
по московскому времени и идут от старых к новым.

```json
{"day":"2026-11-10","openings":4,"people":3,"answered":2,"sources":[{"source":"post1","openings":2,"people":2,"answered":1},{"source":"неизвестна","openings":2,"people":2,"answered":2}]}
```

| Поле | Смысл |
| --- | --- |
| `day` | московский день |
| `openings` | число открытий Тренажёра: команда `/train`, пункт меню или ссылка |
| `people` | число разных людей, которые открыли Тренажёр в этот день |
| `answered` | число разных людей, которые в этот день ответили хотя бы на один вопрос |
| `sources` | те же числа по меткам источника |

Правила счёта:

- Открытием считается каждый запрос открыть Тренажёр, даже если Telegram не доставил виджет.
- Метка источника берётся из ссылки `/start train_<метка>`. Открытия без метки (команда, меню,
  ссылка без метки или с испорченной меткой) идут в строке `"source": "неизвестна"`. Настоящая
  метка так называться не может: в метках разрешены только латинские буквы, цифры, `_` и `-`.
- `answered` в строке метки показывает, сколько людей из её `people` ответили на вопрос в тот же
  день.
- Человек, который за день пришёл с двумя метками, входит в `people` обеих. Поэтому сумма `people`
  по меткам может быть больше `people` дня.
- `answered` дня считает всех ответивших, в том числе тех, кто отвечал в виджете, открытом в
  другой день. Поэтому в дне без открытий `answered` может быть больше нуля, а список `sources`
  пустым.
