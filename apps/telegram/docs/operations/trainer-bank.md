# Загрузка Банка вопросов Тренажёра

Команда `trainer-bank-import` загружает Банк вопросов в базу бота из одного файла JSON.
Формат файла описан в [контракте Банка](../integrations/trainer-bank-v1.md).
Загрузка настоящего Банка в production требует разрешения владельца.

## Что делает команда

1. Читает файл со стандартного ввода.
2. Проверяет файл целиком: схему, повторы идентификаторов, лимиты длины и байтов.
3. Если есть хотя бы одна ошибка, ничего не меняет в базе и печатает отчёт об ошибках.
4. С ключом `--preview` печатает, что изменит загрузка, и ничего не пишет.
5. С ключом `--apply` меняет базу одной транзакцией.

Файл передаётся через стандартный ввод, потому что контейнер команды работает с файловой
системой только для чтения и видит только сеть базы.

## Запуск в production

Переменная `telegram_compose` задаётся как в разделе
[operations-команд](production.md#operations-команды). Файл Банка лежит на сервере вне Git.

```bash
"${telegram_compose[@]}" --profile operations run --rm -T trainer-bank-import --preview < /protected/trainer-bank.json
"${telegram_compose[@]}" --profile operations run --rm -T trainer-bank-import --apply < /protected/trainer-bank.json
```

Сначала выполните `--preview` и прочитайте отчёт. Затем выполните `--apply` с тем же файлом.

## Запуск локально

Из `apps/telegram`, с `DATABASE_URL` своей базы:

```bash
pnpm owner:trainer-bank-import --preview < docs/integrations/trainer-bank-v1.example.json
```

## Отчёт

Отчёт печатается в стандартный вывод как JSON. Текстов вопросов и вариантов в нём нет.

| `status` | Код выхода | Смысл |
| --- | --- | --- |
| `valid` | 0 | `--preview`: файл корректен, база не менялась |
| `imported` | 0 | `--apply`: база соответствует файлу |
| `rejected` | 2 | файл отклонён, база не менялась |

Код выхода 1 означает, что команда вызвана неверно, файл не является JSON или база недоступна.
База при этом не меняется.

Корректный файл:

```json
{
  "status": "imported",
  "topics": 2,
  "questions": { "added": 2, "updated": 0, "unchanged": 0, "restored": 0, "withdrawn": 0 }
}
```

| Счётчик | Смысл |
| --- | --- |
| `added` | новые вопросы |
| `updated` | вопросы в показе, у которых файл изменил содержимое |
| `unchanged` | вопросы в показе без изменений |
| `restored` | снятые раньше вопросы, которые вернулись в файл |
| `withdrawn` | вопросы, которых нет в файле; они сняты с показа и остались в базе |

Отклонённый файл:

```json
{
  "status": "rejected",
  "errors": [
    { "question": "t1-0001", "field": "text", "reason": "Текст вопроса: знаков 161, лимит 160." }
  ]
}
```

Каждая ошибка называет вопрос (`question`) или тему (`topic`), поле и причину. Если сам
идентификатор сломан, вместо него стоит номер записи в файле, например `№3`. Исправьте файл в
закрытом репозитории и запустите команду снова.

## Откат

Чтобы вернуть прежний Банк, загрузите прежний файл. Вопросы и история ответов при этом не
удаляются: загрузка только обновляет содержимое, снимает и возвращает вопросы.
