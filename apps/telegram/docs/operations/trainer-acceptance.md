# Приёмка Тренажёра

Локальный просмотр даёт пройти все режимы до проверки на телефоне. Он использует собранный
виджет приложения и настоящий модуль Тренажёра с PostgreSQL. Браузер заменяет Telegram только
на границе запроса и ответа. Webhook, доставка через Telegram и ограничения клиента этим
просмотром не проверяются.

## Открыть просмотр

Нужны запущенный Docker, зависимости репозитория и Node.js из `.node-version`. Из корня:

```bash
pnpm --filter @inside/telegram trainer:review
```

Команда создаёт свой проект Compose с именем `trainer-review-<код>`, поднимает PostgreSQL на
случайном порту `127.0.0.1`, создаёт внутри него новую базу со случайным именем, применяет миграции и загружает синтетический Банк. Бот-токен,
`DATABASE_URL` и настоящие вопросы она не читает. Внешних сообщений нет. Общий стенд не меняется.
В конце запуска команда печатает адрес просмотра, PID и имя проекта.

Открой напечатанный адрес. Вопросы намеренно условные: для вопроса с одним правильным ответом
верен А; в каждом третьем вопросе верны А и Б. Это позволяет проверить вердикты без подготовки
Банка. Кнопка «Начать новым участником» даёт пустую историю, не удаляя ответы предыдущего
участника. Открытые вкладки используют одного текущего синтетического участника.

## Сценарий на 5–10 минут

| Действие | Ожидаемый результат |
| --- | --- |
| На главном нажми «Проверить себя» | Начинается раунд из 5 вопросов разных тем |
| Переключай главный экран, вопрос, разбор, Прогресс и Рейтинг | Высота следует содержимому без большого пустого хвоста; нижний край закреплён в клиентах с поддержкой этого метода |
| Открой вопрос с условием (в Банке есть поле `context`) | Сначала экран условия с кнопкой «К вопросу». На экране вопроса кнопка «Условие» возвращает к нему, отмеченные варианты сохраняются |
| Ответь один раз верно, один раз неверно и один раз «Не знаю» | Вопрос и все варианты остаются на экране. Карточки и шрифт не меняют размеры и положение. Панель снизу показывает зелёный или красный вердикт и разбор, длинный разбор листается стрелками. Варианты больше не нажимаются |
| После разбора нажимай «Дальше», после последнего «К итогу» | Вопросы сменяются, после пятого ответа появляется итог |
| Вернись на главный и открой Вопрос дня | Получаешь один вопрос. После ответа есть доля верных и число ответивших |
| Открой Вопрос дня снова | Сохранён прежний ответ, второй ответ не принимается |
| В Тренировке по теме выбери любую тему | Раунд содержит до 10 вопросов этой темы, итог называет тему |
| Ответь на один вопрос нового раунда и выйди | Очки, Серия, Цель дня, Прогресс и Рейтинг не изменились; после завершения всего раунда ответы зачтены один раз |
| Листай темы и Прогресс стрелками | На странице до трёх тем, доступны все страницы |
| Открой Прогресс | Видны ответы, Очки, Серия и счётчики тем. Вопросы с верным первым быстрым ответом дали очки |
| После ответа оцени вопрос | Кнопка «Оценить» открывает лайк и дизлайк. Они заменяют друг друга и снимаются повторным нажатием. Варианты не сдвигаются; учебные показатели не меняются |
| Отправь `/start` и нажми «Тренажёр» | Виджет открывается без покупки и привязки аккаунта |
| Открой Рейтинг | Участники с очками показаны автоматически. Предложения участия и переключателя нет; есть вкладки недели и всего времени, при наличии очков есть твоя строка |
| Выбери нового участника, переключи тему и ширину 320 | Прогресс нового участника пуст, текст и кнопки помещаются в узком виджете |
| Повтори короткий раунд в тёмной теме | Цвета читаются, выбранные и верные варианты различимы |

Переключение темы или ширины пересоздаёт виджет и показывает исходный главный экран сообщения,
как при пересоздании Telegram. «На главный» внутри виджета запрашивает свежие счётчики.

Для замечания достаточно написать шаг, тему, ширину и что получилось вместо ожидаемого.
Если помогает, приложи снимок экрана. Успешный локальный просмотр не является согласием на выпуск.

## Отдельно на телефоне

В [#2002](https://github.com/sachkov-inside/platform/issues/2002) остаются проверки настоящего
Telegram в светлой и тёмной теме:

- все режимы, высота экранов и читаемость при выбранном размере текста;
- нажатие доходит до бота как `widget_query`, виджет получает ответ, записано время ответа;
- подписи снизу нет, время в нижнем углу не перекрывает кнопки;
- поведение старого клиента без поддержки виджета;
- сервер принимает HTML в пределах лимита, прямые вызовы Bot API работают;
- после закрытия и повторного открытия сообщения проверены счётчики и сохранение ответов;
- защищённый личный чат и вход по ссылке с меткой работают.

Для этих пунктов нужен отдельно подготовленный тестовый бот. Локальная команда его не создаёт
и не настраивает. Настройка BotFather, выпуск, загрузка настоящего Банка и рассылки сохраняют
отдельные разрешения владельца.

## Остановить просмотр

Нажми Ctrl+C в терминале команды или отправь SIGTERM напечатанному PID. Сервер закроется,
его контейнер PostgreSQL и том удалятся. При следующем запуске будет новая пустая база.

Если процесс аварийно убит через SIGKILL, запись его ресурсов остаётся в
`.reports/trainer-review/trainer-review-<код>.json`. Она содержит только имя проекта, PID и
локальный URL. Для удаления этого проекта используй его точное имя из записи:

```bash
COMPOSE_PROJECT_NAME=trainer-review-<код> TELEGRAM_POSTGRES_PORT=0 TELEGRAM_AMQP_PORT=0 TELEGRAM_MANAGEMENT_PORT=0 \
  docker compose -f apps/telegram/compose.yaml down --volumes
```

Перед ручной командой Compose сначала выполни `docker compose ps` по правилам локального стенда.
Чужие проекты, контейнеры и тома не удаляй.
