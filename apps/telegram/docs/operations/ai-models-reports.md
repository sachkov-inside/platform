# Отчёты автора по «ИИ-моделям»

Команда `ai-models-report` печатает один из двух отчётов по разделу «ИИ-модели»:

- `--usage`: сколько раз и сколько людей открыли раздел, по московским дням и меткам источника;
- `--cards`: сколько раз и сколько людей открыли карточку каждой модели, за всё время и за
  последние 7 дней.

Команда только читает базу бота: открытия раздела (`ai_models_openings`) и открытия карточек
(`ai_models_card_views`). В отчётах нет имён, username и идентификаторов Telegram: они считают
людей, но не называют их. Запуск в production требует разрешения владельца.

## Запуск в production

Переменная `telegram_compose` задаётся как в разделе
[operations-команд](production.md#operations-команды). Контейнер команды видит только сеть базы.

```bash
"${telegram_compose[@]}" --profile operations run --rm -T ai-models-report --usage
"${telegram_compose[@]}" --profile operations run --rm -T ai-models-report --cards
```

## Запуск локально

Из `apps/telegram`, с `DATABASE_URL` своей базы:

```bash
pnpm owner:ai-models-report --usage
pnpm owner:ai-models-report --cards
```

## Вывод и коды выхода

Отчёт печатается в стандартный вывод, одна строка JSON на день или на модель. Если строк нет,
вывод пустой. Чтобы сохранить отчёт, перенаправьте вывод в файл вне Git.

| Код выхода | Смысл |
| --- | --- |
| 0 | отчёт напечатан |
| 1 | команда вызвана без `--usage` или `--cards`, с лишними аргументами, без `DATABASE_URL`, или база недоступна |

## Отчёт по использованию

Одна строка на каждый день, в который кто-то открыл раздел. Дни считаются по московскому времени
и идут от старых к новым.

```json
{"day":"2026-11-14","openings":5,"people":3,"sources":[{"source":"digest","openings":1,"people":1},{"source":"post1","openings":2,"people":2},{"source":"неизвестна","openings":2,"people":2}]}
```

| Поле | Смысл |
| --- | --- |
| `day` | московский день |
| `openings` | число открытий раздела: команда `/models`, текст «ИИ-модели», кнопка меню или ссылка |
| `people` | число разных людей, которые открыли раздел в этот день |
| `sources` | те же числа по меткам источника |

Правила счёта:

- Открытием считается каждый запрос открыть раздел, даже если Telegram не доставил виджет.
- Запрос до первой загрузки Справочника тоже считается открытием. Человек получил текст
  «Раздел «ИИ-модели» скоро откроется.», но раздел он просил, и метка ссылки показывает, откуда
  он пришёл.
- Повтор того же обновления Telegram второго открытия не добавляет.
- Метка источника берётся из ссылки `/start models_<метка>`. Открытия без метки (команда, текст,
  кнопка меню, ссылка без метки или с неверной меткой) идут в строке `"source": "неизвестна"`.
  Настоящая метка так называться не может: в метках разрешены только латинские буквы, цифры, `_`
  и `-`.
- Метки дня идут по алфавиту, строка `неизвестна` последней.
- Человек, который за день пришёл с двумя метками, входит в `people` обеих. Поэтому сумма
  `people` по меткам может быть больше `people` дня.

## Отчёт по карточкам

Одна строка на каждую модель, карточку которой кто-то открыл. Первой идёт модель с наибольшим
числом открытий. При равном числе открытий раньше идёт модель, которую открыло больше людей, а
дальше модели идут по коду.

```json
{"model":"gpt-5","views":12,"people":7,"last7Days":{"views":5,"people":3}}
```

| Поле | Смысл |
| --- | --- |
| `model` | код модели из Справочника |
| `views` | сколько раз открыли вкладку «Главное» карточки модели за всё время |
| `people` | число разных людей, которые открыли карточку модели |
| `last7Days` | те же числа за последние 7 московских дней, включая сегодняшний |

Правила счёта:

- Каждое открытие вкладки «Главное» считается отдельно, в том числе повторное тем же человеком.
  Вкладка «Подписки» в отчёт не входит.
- Последние 7 дней отсчитываются от дня запуска команды по московскому времени. Отчёт, запущенный
  14 ноября, считает в `last7Days` открытия с 00:00 8 ноября.
- В отчёте нет модели, карточку которой никто не открывал.
- Модель, которую убрали из Справочника, остаётся в отчёте со всеми своими открытиями.
