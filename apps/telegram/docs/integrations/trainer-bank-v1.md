# Файл Банка вопросов Тренажёра, версия 1

Это контракт между закрытым репозиторием Банка вопросов и ботом. Автор ведёт вопросы в закрытом
репозитории и собирает из них один файл JSON. Владелец загружает файл в базу бота
[командой импорта](../operations/trainer-bank.md).

В этом репозитории нет вопросов с ответами. Пример и тесты используют синтетический банк.

| Файл | Назначение |
| --- | --- |
| [trainer-bank-v1.schema.json](trainer-bank-v1.schema.json) | JSON Schema формы файла и лимиты в поле `x-limits` |
| [trainer-bank-v1.example.json](trainer-bank-v1.example.json) | синтетический пример корректного файла |

Схему нельзя править руками. Она собирается из схемы, по которой проверяет импорт
(`src/modules/trainer/trainer-bank-file.ts`), командой `pnpm --filter @inside/telegram trainer:bank:schema`.
Проверка `pnpm --filter @inside/telegram check` падает, если опубликованная схема отстала от кода.

## Состав файла

Файл хранит весь Банк целиком: список тем и список вопросов. Кодировка UTF-8.

**Тема** (`topics`): код `code` и название `name`. Порядок тем в файле задаёт порядок тем в
Тренажёре. Код темы постоянный: строчные латинские буквы и цифры, до 16 знаков. Название можно
менять от загрузки к загрузке.

**Вопрос** (`questions`):

| Поле | Смысл |
| --- | --- |
| `id` | постоянный идентификатор; по нему бот узнаёт вопрос при повторной загрузке |
| `topic` | код темы из `topics` |
| `format` | `single`: ровно один верный вариант; `multiple`: не меньше двух верных |
| `context` | необязательное условие: ситуация, которую человек читает на отдельном экране перед вопросом |
| `text` | текст вопроса; может быть пустым, только если задано `context` |
| `options` | от 2 до 4 вариантов; у каждого `text`, `correct` и `explanation` (разбор варианта) |
| `explanation` | общий разбор |
| `source` | источник, по которому автор проверил вопрос |
| `checkedAt` | дата проверки в виде `ГГГГ-ММ-ДД` |

`source` и `checkedAt` нужны автору. Бот хранит их и не отправляет в виджет.

Неизвестное поле отклоняет файл, чтобы опечатка в имени поля не прошла незаметно.

## Правила сверх схемы

Импорт проверяет файл целиком. Числа лимитов лежат в `x-limits` схемы и берутся из замеров
виджета ([ADR 0004](../adr/0004-trainer-html-widget.md)).

1. Идентификаторы вопросов и коды тем не повторяются.
2. Каждый вопрос ссылается на тему из файла. У каждой темы есть хотя бы один вопрос.
3. Тем не больше `topics`, название темы не длиннее `topicNameCharacters`. Данные каждой страницы тем (не больше трёх тем)
   вместе с кодами, названиями и наибольшими счётчиками текущего Банка укладываются в
   `topicsDataBytes` байт. Каждая страница Прогресса с наибольшими счётчиками укладывается в `progressDataBytes` байт.
4. Текст вопроса не длиннее `questionTextCharacters`. Он может быть пустым, только если у вопроса
   есть `context`.
5. Условие `context` не длиннее `questionContextCharacters`, а его данные для виджета укладываются
   в `questionContextDataBytes` байт.
6. Тексты всех вариантов вопроса вместе не длиннее `optionTextsTogetherCharacters`.
7. Разбор, который человек видит после ответа, не длиннее `answerExplanationCharacters`.
   Он состоит из разборов выбранных вариантов в порядке файла и общего разбора, через пробел.
   Импорт считает каждый возможный ответ: в формате `single` это один любой вариант, в формате
   `multiple` любой набор вариантов. Ответ «Не знаю» показывает только общий разбор.
   Бот сам режет разбор на части по `answerExplanationDataBytes` байт, поэтому отдельной проверки
   байт у разбора нет.
8. Данные вопроса (название темы, текст и варианты) укладываются в `questionDataBytes` байт ответа
   виджету.

Лимиты знаков это грубая граница. Условие и варианты у верхних границ вместе в один ответ не
помещаются: решает счёт байт. Если данные вопроса не проходят, перенеси часть текста вопроса в
`context`, вплоть до пустого `text`. Условие до `questionTextCharacters` знаков остаётся в `text`,
поле `context` для него не нужно.

Импорт не видит экрана. Помещается ли вопрос в виджет, показывает команда, которая рисует каждый
вопрос файла в собранном виджете при ширине 320 и 390 px:

```bash
pnpm --filter @inside/telegram trainer:widget:fit <файл Банка>
```

Она рисует экран условия, экран вопроса и каждую страницу разбора для каждого ответа, который
может отправить виджет: «Не знаю» и каждый вариант в формате `single`, любой набор вариантов в
формате `multiple`. На вопрос и ширину печатается одна строка JSON: идентификатор, байты данных,
шрифт и высота экранов условия и вопроса, число проверенных ответов и страниц, наибольшая высота
и наименьший шрифт среди них, знаки, части и страницы самого длинного разбора. Текстов Банка в
выводе нет. Код выхода 1, если хотя бы один экран выше 560 px или шрифт мельче 11 px; код 2, если
файл не проходит проверку импорта. Команде нужен `pnpm exec playwright install chromium`; Банк из
235 вопросов она проходит примерно за 7 минут.

Длина считается в знаках после приведения текста к составной форме Юникода (NFC). Пробелы по
краям текста импорт убирает. Байты считаются в UTF-8 вместе с JSON-обёрткой ответа: кириллица
занимает 2 байта на букву, знаки вроде `€` и `→` занимают 3 байта, кавычка занимает 2 байта.
Поэтому текст может пройти по знакам и не пройти по байтам.

## Что делает повторная загрузка

- Вопрос с тем же `id` обновляется на месте. Ответы и очки по нему сохраняются.
- Бот сохраняет редакции текста, вариантов и разбора. Уже показанная выдача продолжает использовать
  свою редакцию, включая повторное открытие Вопроса дня. Ещё не показанные шаги раунда и новые
  выдачи получают актуальную редакцию.
- Редакции, затёртые до появления хранения версий, нельзя восстановить из текущего Банка.
  Если прежняя редакция недоступна, бот сохраняет оценку ответа и очки, но не подставляет новый
  текст или разбор под прежний выбор.
- Миграцию хранения редакций можно откатить, пока таблица содержит только текущие редакции.
  После сохранения прежних редакций откат отказывается удалять историю. Для возврата к схеме
  до этой миграции нужна проверенная резервная копия, созданная перед обновлением.
- Вопрос, которого нет в новом файле, снимается с показа и остаётся в базе вместе с историей.
- Снятый вопрос возвращается в показ, когда снова появляется в файле с тем же `id`.
- Тема, которой нет в новом файле, пропадает из списка тем. Её вопросы либо переходят в другую
  тему файла, либо снимаются с показа.

Не используйте `id` повторно для другого вопроса: бот посчитает его правкой прежнего и сохранит
за ним старые ответы.
