# Отчёт агента

Отчёт — папка `<основной каталог проекта>/.reports/<задача>/<дата>-<имя>/`. Владелец читает его на
локальной странице отчётов. Ядро `report.json` рисует страница, тело по желанию пишешь ты.
Краткий итог по-прежнему идёт в PR.

Когда отчёт обязателен и какие команды считаются проверкой, говорит правило pipeline проекта.
Общее условие: отчёт пишется, когда работа сдаётся владельцу.

## Шаги

1. Создай папку с фактами из git, tracker и Herdr:

   ```bash
   python3 <каталог skill>/report.py new --task <номер|ссылка|строка> --name <короткое-имя>
   ```

   Команда печатает путь папки. Ветку, worktree, PR и сессию она берёт сама: из привязки сессии,
   иначе из текущего каталога. Работал в другом worktree, а привязки нет — передай
   `--worktree <путь>`. Проект без tracker передаёт задачу строкой.
2. Собери факты: `git log` и `git diff` ветки, состояние задачи и PR, вывод проверок проекта.
   Не пиши по памяти то, что можно получить командой.
3. Заполни ядро в `report.json` по таблице ниже.
4. Реши, нужно ли тело. Выбери форму по лестнице (раздел «Тело»).
5. Сдай отчёт:

   ```bash
   python3 <каталог skill>/report.py finish <папка>
   ```

   Ошибка формы — исправь и запусти снова. Пока `finish` не вернул 0, отчёт не сдан: не называй
   работу сданной.
6. Напечатай владельцу ссылку из вывода `finish` и одну строку итога.

## Ядро `report.json`

| Поле | Что писать |
|---|---|
| `version` | `1` |
| `project` | имя основного каталога проекта; `new` заполняет сам |
| `task` | `{id, title, url}` из tracker либо строка, если tracker нет |
| `title` | необязательно: заголовок, если название задачи его не передаёт |
| `status` | `done` готово, `stopped` остановлено, `review` ждёт приёмки |
| `created_at` | время ISO 8601 с поясом; `new` заполняет сам |
| `summary` | что сделано: от одной до пяти строк простыми словами, кто что сделал |
| `needs_owner` | что нужно от владельца: решение, вход, gate; пустой список, если ничего |
| `verification.auto` | что проверено командой: `{text, command}` или `{text, link}` на CI |
| `verification.manual` | что владелец проверяет сам: `{text, command}` или `{text, link}` |
| `verification.unverified` | что не проверено и почему: `{text}` |
| `next` | что дальше: строки или `{text, link}` |
| `actions` | `{label, prompt, irreversible}`: готовое поручение агенту, которое владелец скопирует |
| `session` | `{agent, id, branch, worktree, pr}`; `new` заполняет сам |

Правила ядра:

- Одна мысль на строку. Числа, имена и пути вместо «некоторые» и «ряд».
- Каждая строка `verification.auto` называет команду или ссылку, которая это доказывает.
  Выполнял команду — пиши её. Не выполнял — пункт идёт в `unverified`.
- `prompt` действия — полное поручение: агент выполнит его без истории чата. Действие, которое
  нельзя отменить (merge, удаление, публикация), получает `"irreversible": true`.
- Не выдумывай действия: только то, что владелец разумно поручит следующим шагом.

## Тело: лестница форм

Тело не обязательно. Оно не повторяет ядро, а объясняет то, что ядру не по силам. Поднимайся на
ступень выше только с названной причиной.

1. **Нет тела.** Ядра хватает: так в большинстве задач.
2. **Текст** — `body.md`: подробное объяснение решения или находки.
3. **Диаграмма** — `body.html` с inline SVG: поток, структура, «было и стало».
4. **Интерактивная страница** — `body.html` со скриптом: владелец сам переключает варианты.
5. **Видео или анимация** — `assets/` и `body.html`. Анимация допустима, когда объясняет, а не
   украшает.

Как выбрать вид внутри тела (из skill `pr` Matt Pocock):

- Логика или алгоритм — псевдокод. Поток вызовов — дерево вызовов.
- Структура интерфейса — дерево компонентов. Раскладка файлов — короткое дерево файлов.
- Взаимодействие частей или поток данных — схема последовательности.
- Что поменялось при сохранённой форме — `diff` этой формы.
- Доказательство «до и после»: снимок экрана для видимого изменения, вывод теста или команды для
  остального. Покажи тест, который падал и теперь проходит.
- Цена ошибки: дверь в одну сторону или в обе, радиус поражения. Пиши это, когда сдаёшь PR.

Оставляй в теле только то, что нужно для текущего вопроса. Не используй всё сразу.

Техника тела:

- `body.html` — самостоятельная страница: стили и SVG внутри файла, картинки из `assets/`
  относительной ссылкой. Внешние скрипты не подключай.
- Страница показывает тело в `iframe sandbox`: у него нет доступа к странице, буферу и кнопкам.
  Кнопки действий рисует только страница из `actions`.
- Учитывай светлую и тёмную тему: `@media (prefers-color-scheme: dark)`.
- В `body.md` работают заголовки, абзацы, списки, код и ссылки. Диаграмму клади в `body.html`.

## Образцы

- `examples/core-only/` — только ядро.
- `examples/with-diagram/` — ядро и диаграмма в `body.html`.

## Страница отчётов

Ссылка из `finish` ведёт на `http://127.0.0.1:7451/r/<id>`. Страница живёт в репозитории
`workspace` (`page/`), находит отчёты сканом каталогов проектов и обновляется сама. В Herdr её
открывает клавиша отчёта сфокусированной сессии.
