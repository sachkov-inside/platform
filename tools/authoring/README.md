# Формат переноса

Текущий пакет использует `schemaVersion: 3`, `selection.productId`, `products` и обязательную
возможность `canonical-product-source-v2` в `requiredFeatures`. Поле `showInFeed` запрещено
в материалах и страницах Tasks. Пакет v3 не принимает старые структурные имена `guides` и
`selection.guideId`. Формат материала `guide`, авторские тексты и постоянные source IDs сохраняются.

Перед изменениями `syncLocal`, release preview и команда доставки проверяют контракт получателя
из `/authoring/import/materials/environment`. Текущий контракт имеет `version: 2`. Новые запросы
передают `source: { version: 2, id, path, revision, commit? }`, `metadata.productIds` и `productId`
для состава Product и закрепления на Home. Чтение принадлежности использует `productMemberships`.
Предпросмотр больше не предлагает изменение появления в ленте.

## Исторические пакеты и неизвестный результат запроса

Декодер продолжает принимать строгие пакеты v1/v2. Их исходные байты определяют package ID,
а полный исторический материал, включая `showInFeed`, определяет исходную Material revision.
Старый Practice source reference проверяется до преобразования требований в Task. Удалять поле
из такого пакета или перезаписывать оригиналы для перехода на v3 нельзя. Сохранённые авторские
`body`, `page` и `definition` остаются непрозрачными для переименования.

Journal сохраняет исходный запрос, его ключ и receipt. Неизвестный результат старого Material
запроса проверяется через `/authoring/history/material-receipts`, старого Practice запроса через
`/authoring/history/practice-receipts`. В lookup уходят исходное тело и исходный idempotency key.
Lookup не исполняет прежнюю запись. Старый journal не хранит исходного actor, поэтому даже
`404 historical_receipt_not_found` может означать вход под другим Account, а не отсутствие
исходной операции. Любая ошибка lookup сохраняет исходные key/body и pending с требованием
восстановления. Только найденный receipt исходного автора разрешает неизвестный результат.
Поиск чужих receipts и повтор прежней записи не выполняются.

Для старых изменяющих команд без immutable receipt lookup, в том числе состава с `seriesId`
и Tasks с прежними структурными именами, автоматический повтор не обещан. Перенос останавливается
до изменений с требованием явного восстановления. Journal остаётся для сверки с текущим состоянием
владельца. Нельзя придумывать успешный receipt или повторять старую команду через новый обработчик.

Новый план использует текущий Task importer. Старый Practice writer не используется для новых
требований. Существующие Tasks с подтверждённой исторической привязкой сохраняют immutable version,
публикацию и metadata. Неоднозначная привязка или неизвестный незавершённый Task требуют сверки.
